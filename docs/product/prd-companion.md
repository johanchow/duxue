## 一、背景与目标

### 1.1 产品定位

在 Ward（学生）按照已确认的计划进入学习执行阶段时，为其提供“沉浸式任务陪伴、苏格拉底式启发答疑、好奇心与兴趣信号捕获、轻量成就收尾”的综合伴学体验。

本能力服务于产品架构中的三大核心目标：
- **G1（提升专注力与自制力）**：提供无干扰的专注节奏支持与适时休息建议，不做侵入式监工，维护孩子自主进入心流状态的心理安全感；
- **G2（养成自主驱动学习探索的习惯）**：通过“启发提示而非直接给答案”引导孩子经历独立思考和克服卡点的成就感；对学习过程中的好奇心发散给予正面承接并沉淀为兴趣探索信号；
- **G3（优化家庭关系）**：AI 承担高频、即时、消耗精力的学科答疑与在场陪伴负担，将 Guardian 从“随时随地被叫去讲题、易产生焦躁对抗”的认知压力中解放出来。

### 1.2 核心设计原则

1. **启发式支架引导，坚决不做“直接报答案的答题器”**：系统的核心价值是引导孩子思考（审题拆解、概念提示、同类例题），严禁直接输出最终解题答案或代写内容，避免滋生作业作弊与思维惰性。
2. **安静在场的学伴，严禁成为“电子监工”**：在陪伴执行过程中，系统提供温和的计时与节奏支持。行为观测（5.4）在后台静默运行且为次日批量复盘，伴学界面绝不出现实时的“分心警告”“专注度扣分”等红字呵斥，不打断孩子当下思路。
3. **保护好奇心，将发散问题转为兴趣信号而非单纯判定为分心**：孩子在做作业时提出看似无关的问题（如“蚂蚁为什么能认路”），AI 给予精炼解答并底层标记为 `Interest Signal` 存入孩子理解引擎，同时温和引导其收敛回当前任务，绝不斥责孩子“胡思乱想”。
4. **多模态低门槛交互，适配未成年人表达习惯**：支持拍照圈题、语音提问与文字输入；输出支持结构化分步卡片、生动图文提示与语音播报，让低龄段学生也能轻松交互。
5. **学习过程结构化沉淀，反哺次日复盘与成长画像**：伴学期间的提问点、卡壳耗时、尝试轮次，自动沉淀为“过程事实证据”，供次日结果评估（5.6）及长期成长画像诊断。
6. **拒绝形式主义，无感收尾保护心流**：学习的关键环节是专注心流与独立思考，而非形式化的打卡留痕。伴学模块坚决不要求学生在任务完成后拍照上传作业，不增加任何形式化工作；任务完成时一键顺畅收官，给予纯粹的正向成就激励，让学生轻松享受心流成就感。

### 1.3 本期目标

- 提供 Ward 专属的“任务伴学工作台”：支持已确认计划任务的启动、计时、暂停与一键顺畅收尾；
- 实现多模态（文本、语音、图片框选）的 AI 启发式分步答疑能力，覆盖常见中小学基础学科；
- 建立多级提示（Hinting Hierarchy）机制：审题提示 → 关键概念 → 解题步骤拆解 → 类似例题，多轮交互卡壳时才提供完整思路讲解；
- 实现做题过程中的“兴趣信号识别与沉淀”机制，温和平衡即时好奇心解答与当前任务聚焦；
- 实现任务完成时的轻量成就总结（专注时长、攻克卡点数与温馨鼓励），坚决不做形式化作业拍照上传；
- 建立青少年内容安全防护与作弊/代写拦截规则；
- 沉淀问答过程数据，为次日复盘（5.6）提供客观卡点证据。

### 1.4 非目标

- 不做拍照直接出整卷/整页作业答案的“拍照搜题”工具；
- 不提供整篇作文代写、文段全自动代做等直接代劳功能；
- 不在任务完成时强加作业拍照归档、打卡留痕等形式主义操作；
- 不在执行页面提供实时的摄像头视觉分心告警或语音呵斥（违背非监工原则）；
- 不做无限制的开放式娱乐聊天（防沉迷机制控制闲聊轮次）；
- 不做替代专业教师体系的完整知识点视频大课教学；
- 不在本期支持实时多学生连麦组队自习室等社交功能。

### 1.5 建议衡量指标

以下指标用于自用验证期验证产品体验与算法效果，阈值在数据积累后动态校准：

- **北极星指标**：Ward 遇到难题时，通过启发式引导自主得出答案的会话闭环率（而非中途放弃或索要答案后退出）；
- **启发有效性**：单次答疑中，仅通过前两级提示（审题/概念提示）即完成解题的比例；
- **作弊拦截率**：直接索要答案、代写整篇作业的请求被成功拦截并转入引导式提问的比例（目标 > 95%）；
- **答疑满意度/体感**：Ward 提问后主动点击“我明白了/有思路了”的正向反馈占比；
- **答疑响应延迟**：文字/语音提问的首字流式返回 P90 < 2.0 秒，图片解析首步返回 P90 < 4.0 秒；
- **兴趣捕获质量**：伴学过程中捕获的兴趣信号在后续深度引导中被采纳为探索任务的转化率；
- **任务顺畅完成率**：进入伴学工作台并顺利完成既定任务的比例（体现无形式负担下的自主收尾体验）。

### 1.6 名词解释

| 名词 | 解释 |
|------|------|
| 任务伴学工作台 | Ward 点击开始执行某个已排期任务时进入的专注界面，集成任务信息、专注计时、AI 启发答疑唤起与轻量成就结算 |
| 独立 AI 伙伴 | Ward 位于底部导航的常驻 AI 交互空间，用于自由探索、学科提问、日常好奇心解答及历史问答回顾 |
| 支架式教学（Scaffolding） | 一种教育方法，AI 根据学生的当前能力提供适度支持（分步线索），并随着学生理解加深逐步撤去支持 |
| 提示阶梯（Hinting Hierarchy） | 系统内建的 4 级递进启发响应模式：L1 审题反问 → L2 关键线索 → L3 分步例题 → L4 思路详解与自我检验 |
| 兴趣信号（Interest Signal） | Ward 在执行或对话中表现出的超出当前既定学科任务的好奇心和探索意向数据 |
| 任务成就卡片 | 任务完成后即时展示的极简成就反馈（包含专注用时、攻克卡点摘要与正面激励），不附加任何作业照片或评判数据 |
| 卡点记录（Stuck Point） | Ward 产生提问或长时间停顿对应的学科知识点、题型与交互时段，作为后续复盘依据 |

## 二、目标用户与核心场景

### 2.1 核心用户与角色分工

- **Ward（学生，核心使用者）**：在书桌前执行具体学习任务（写作业、朗读、预习、兴趣探索），遇到卡点时随时唤起 AI 进行文字、语音或拍照答疑；任务结束时一键轻量收尾并获得成就反馈，无任何拍照打卡负担。
- **Guardian（家长，观察者与支持者）**：无需在书桌旁全程盯梢讲题；在次日报告中了解孩子的学习专注表现与卡点提问摘要，彻底免于日常作业打卡监督的烦琐。

### 2.2 核心用户旅程

```text
用户旅程：小宇在 AI 伴学下的一个任务执行闭环
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【场景一：任务伴学与遇到难题】
Step 1：小宇在首页点击今日计划中的“数学练习册 P23-25 [开始学习]”
        → 系统进入“任务伴学工作台”，开始计时，并提示“伴学中，遇到问题随时问我”
        → 伴学设备同时处于“学习观察/采集”状态（后台静默运行）
        → 小宇感知：桌面整洁专注，没有大喇叭监控感，只有贴心的伴学助手

Step 2：做至应用题第 3 题（鸡兔同笼变体）时卡壳，小宇点击“拍照圈题”，框选题目并语音补充“这道题我不知道怎么列式”
        → 系统极速识别题目文本与图表，分析知识点为“假设法/二元关系”
        → AI（L1 提示）回复：“这道题问的是两种动物各有几只。小宇，先看看题里给出的‘头数’和‘脚数’总共是多少？”
        → 小宇感知：AI 像一个耐心的家教老师在引导我读题，而不是直接把算式扔给我

Step 3：小宇回答：“头有 10 个，脚有 28 只。”
        → AI（L2 提示）继续引导：“太棒了！如果我们假设这 10 只全都是鸡，那一共有多少只脚？和题目里的 28 只有什么差距呢？”
        → 小宇在草稿纸上计算：10 × 2 = 20，差 8 只脚。每把一只鸡换成兔子，就多 2 只脚，8 ÷ 2 = 4 只兔子！
        → 小宇在界面点击“我算出来了！有 4 只兔子、6 只鸡”，AI 给予正向鼓励
        → 小宇感知：这是我自己一步步解出来的，超级有成就感！

【场景二：偶发好奇心与兴趣分流】
Step 4：做完数学第 4 题，小宇突然语音问：“AI，蚂蚁为什么能找到回家的路呀？”
        → AI 识别为【高好奇心/非任务学科提问】
        → AI 给出 2 句话生动解答：“蚂蚁会沿路留下特殊的气味（信息素），还会利用太阳位置导航哦！”
        → AI 随后温和提示：“这个问题真有趣，我已经帮你把‘蚂蚁认路’放进周末的探索灵感本啦！我们先把最后一道数学题冲刺完，好不好？”
        → 系统在后台生成一条 Interest Signal 沉淀至孩子模型
        → 小宇感知：我的好奇心没有被泼冷水，而且能安心收心继续做题

【场景三：任务自然收尾与成就激励】
Step 5：小宇做完练习册所有题目，点击“完成学习”
        → 系统弹出极简成就卡片：“太棒了！本次专注用时 38 分钟，自己攻克了 1 个卡点！”
        → 系统不弹出任何作业拍照或打卡留痕要求，小宇点击“休息一下”，轻松退出伴学工作台
        → 后台自动将伴学过程事实与计时记录同步至系统，供次日复盘对比使用
        → 小宇感知：做完任务就能干脆地去休息，没有烦人的拍照留痕要求，很有掌控感和轻松感
```

### 2.3 关键异常路径

- **学生直接索要答案（“把答案告诉我 / 选 A 还是选 B”）**：AI 拒绝直接输出选项/答案，转换为问答支架，用鼓励语气引导孩子一步步探索；
- **网络波动或断网**：伴学本地计时继续运行，问答提示“网络正在连接，请稍候”，已输入的草稿与本地题目切图暂存不丢，网络恢复后一键重试；
- **题目拍照模糊或题干残缺**：AI 提示“图片边缘有点模糊/题干不完整哦，请重新对准题目拍一张”，并框出建议取景区域；
- **涉及违规、敏感或负面极端情绪**：触发内容安全拦截，给予温和安抚，严重风险即时同步 Guardian；
- **超范围生僻难题**：AI 评估置信度不足时，坦诚告知“这道题目有点难，我也没完全把握，建议记在卡点本上明天问问老师”，绝不胡编乱造。

## 四、功能需求（MoSCoW 架构）

### 4.1 Must Have（首期核心能力）

#### 4.1.1 伴学执行工作台（Study Workbench）

- **触发条件**：Ward 在首页或计划页点击“开始学习”已排期的任务；或在无计划时直接点击“自由学习”。
- **前置条件**：Ward 已登录；若关联计划任务，该任务处于“待执行/执行中”状态。
- **核心交互**：
  1. 页面进入沉浸式伴学态：顶部显示当前任务名称、所属学科、计划时长与当前已执行时长计时器；
  2. 界面中央提供“AI 伴学助手”快捷唤起常驻悬浮/底部入口（支持“拍照圈题”“语音提问”“键盘输入”）；
  3. 提供“暂停”“继续”按钮；若中途离开，提示是否保存进度；
  4. 任务完成时点击“完成学习”，触发任务完成结算与成就激励流程（4.1.4）；
  5. 伴学期间与后台采集服务（5.1）协同工作，但界面上**严格禁止展示任何实时注意力打分、分心红色警告**。
- **边界条件**：
  - 任务最长单次伴学时间上限为 180 分钟（防误触挂机），超过后自动暂停并提示确认；
  - 息屏或切至后台时保持计时，切回时展示当前累计时间。

#### 4.1.2 启发式分步答疑引擎（Socratic Tutoring Engine）

- **触发条件**：Ward 在伴学工作台或“AI 伙伴”独立模块发起学科或题目提问。
- **多模态输入支持**：
  - 拍照/相册选图：支持裁剪与题目框选，自动进行 OCR 与公式识别（LaTeX）；
  - 语音提问：支持按住说话或点击录音，实时转写为文字；
  - 文字输入：支持软键盘与数学符号快捷面板。
- **提示阶梯（Hinting Hierarchy）机制**：
  系统接收到题目后，必须按照以下阶梯递进交互，**严禁首轮直接输出最终选项、数值答案或完整求解过程**：
  1. **Level 1 审题与条件提取（Clarification）**：
     - 反问已知条件、未知量或关键限制（如：“这道题已知哪些数字？要求的是什么？”）；
  2. **Level 2 核心概念与关键第一步（Key Concept & Strategy）**：
     - 指出适用的定理、公式或解题方向（如：“想想周长公式是什么？如果长增加 2 厘米，周长会怎么变？”）；
  3. **Level 3 支架式分步引导与同类简单例题（Scaffolding & Analogy）**：
     - 给出第一步计算的示范，或构造一个数字更简单的同结构小例题帮助理解规律；
  4. **Level 4 完整思路剖析与自我复核（Full Walkthrough & Verification）**：
     - 仅当 Ward 经过 L1~L3 引导仍表示“还是不明白”或连续尝试错误达 3 次以上时，AI 方可给出完整思路解析，但在结尾必须附带一个“验证问答”（如：“现在你知道为什么选 4 了吗？如果是 12 只头会怎样？”），引导孩子自我消化。
- **作弊与直接要答案拦截**：
  - 若输入包含“直接告诉我答案”“选 A 还是 B”“别废话把过程写出来”，AI 统一回复：“我是你的思考学伴，直接给你答案会夺走你变聪明的机会哦！我们先看第一步……”。
- **作文与开放式任务支架**：
  - 严禁直接代写整篇 300~800 字作文；
  - 采用“审题立意 → 结构大纲（开头/中间事例/结尾）→ 好词好句启发 → 孩子写作草稿 → 针对性润色反馈”的共创引导流程。

#### 4.1.3 好奇心与兴趣信号分流捕获（Curiosity Capturing）

- **触发条件**：AI 在伴学对话中检测到 Ward 的提问与当前学科任务无关，但体现出自然的探究欲与好奇心（如自然科普、宇宙天文、历史典故、工程机械等）。
- **核心交互**：
  1. **正面承接**：用通俗生动、适合孩子年龄的 1~3 句话快速解答核心事实，满足当下好奇心；
  2. **收敛回航**：温和提示：“这个知识太酷了！我把它记在你的‘好奇心探索本’里了，等我们把今天的数学做完，周末一起深入探索！现在回到第 4 题吧？”；
  3. **数据沉淀**：系统后台生成结构化 `Interest Signal` 记录（包含提问时间、关键词、所属领域、提问上下文），存入孩子理解引擎（5.5），作为跨周期深度引导的素材；
  4. **数据隔离**：明确将此类提问标记为“好奇探索”，**严禁在次日报告中将其归类为“违规分心行为”**。

#### 4.1.4 任务完成激励与轻量收尾（Task Completion & Lightweight Wrap-up）

- **核心定位**：学习的关键环节是专注心流与独立思考，而非形式主义的成果拍照。伴学模块坚决不引入作业拍照上传环节，避免给学生增加额外的繁琐动作与形式负担。
- **触发条件**：Ward 在伴学工作台点击“完成学习”。
- **核心交互**：
  1. **即时成就反馈**：弹窗呈现极简、温暖的成就结算（包含：任务名称、本次专注用时 vs. 计划预估时长、本次通过 AI 启发自主攻克的难题数量、正向激励语）；
  2. **极简操作路径**：提供“[ 休息一下 ]”或“[ 开始下一个任务 ]”两个主操作按钮，点击后直接退出伴学工作台或无缝切换至下一项计划；
  3. **数据静默同步**：系统在后台静默将任务完成状态、实际用时、问答卡点与启发轮次沉淀至数据库，作为次日结果评估（5.6）自评对比的底层事实依据；
  4. **零阻断原则**：严禁在任务收尾时弹出任何“拍照上传作业”“拍摄写字本”“写作业总结”等强制或阻断式流程。

#### 4.1.5 答疑数据沉淀与复盘事实底座

- 每次提问与启发交互在后台记录结构化上下文：
  - 任务关联 ID、时间戳、学科、题目 OCR 文本、识别出的知识点标签（如：小学数学-分数乘法）；
  - 经历的提示级别（L1/L2/L3/L4）、交互轮次、耗时；
  - 最终状态（自主解出 / 查看了解析 / 标记为待问老师）；
- 该数据作为 ④ 结果评估（5.6）中“自评对比”与“知识卡点诊断”的客观事实依据。

#### 4.1.6 青少年内容安全与安全护栏（Safety Guardrails）

- **违规内容拦截**：对暴力、色情、自残、校园霸凌、不健康游戏等输入实施 100% 毫秒级阻断，输出正面心理关怀文案；
- **极端情绪识别**：识别出“我太笨了想放弃”“我讨厌所有人”等情绪危机输入时，AI 暂停题目辅导，切换为温和情绪抚慰模式，并触发 Guardian 侧的“关爱情绪提醒”；
- **防沉迷与无限制闲聊熔断**：与学习无关的纯无聊闲聊（如连续发表情、玩文字游戏）单次任务中超过 5 轮后，AI 礼貌拒绝继续闲聊并提示专注于手头任务。

### 4.5 业务规则

1. **启发优先原则**：任何学科题目提问，AI 提示词系统（Prompt System）首轮必须默认输出 L1 级别引导，严禁首轮吐出最终结果或全量解析；
2. **确认闭环原则**：只有当 Ward 主动点击“我懂了”或正确回答了验证问题，当前答疑会话才标记为“已掌握”，否则标记为“需巩固”；
3. **好奇心无罪原则**：对于非任务相关的兴趣提问，系统分类引擎必须将其归入 `Interest Signal`，严禁归入负面行为或扣除专注分；
4. **非监工展示原则**：伴学工作台只展示积极的陪伴信息（计时、任务目标、鼓励卡片），所有视觉采集分析数据只能在次日复盘（5.6）流程中由孩子自己比对查看；
5. **零形式主义负担原则**：伴学执行模块聚焦于陪伴与答疑本身，任务完成时严禁设置作业拍照归档、打卡分享等任何形式化要求，确保心流自然收官；
6. **未成年人隐私与音频处理**：提问的语音片段在转写为结构化文本后，原始音频文件在 24 小时内清除，不进行长期录音留存。

### 4.7 需求冲突与取舍

- **冲突一：孩子想要快速要答案写完作业 vs. 教育引导需要启发式多轮互动**
  - **取舍**：坚守“启发式引导，不给直接答案”。但在交互上尽量轻量友好（每次提示控制在 2~3 句话以内，配合卡片点选，避免长篇说教让孩子产生挫败感）。
- **冲突二：做作业中途发散提问属于“分心”还是“好奇心”**
  - **取舍**：在认知上定性为“珍贵的兴趣信号”，给予快速解答并暂存为探索笔记，但在行为节奏上用温和文案及时引导回到当前任务，兼顾好奇心保护与任务专注。
- **冲突三：伴学需要了解专注情况 vs. 实时监控会毁掉信任**
  - **取舍**：将“采集观测”与“伴学呈现”物理隔离。执行界面纯粹作为专注助手和计时器，行为分析数据全部延后至次日复盘页面，由孩子自评后再呈现对比。
- **冲突四：是否需要让学生在任务结束时拍照上传作业以“留痕证明”**
  - **取舍**：坚决**不设置**作业拍照归档环节。客观行为观测已有后台设备静默采集，答疑数据已有结构化会话沉淀；作业拍照既不是学习的关键环节，又会破坏学生刚完成学习时的成就感与放松感，属于典型的形式主义工作，应予以彻底剥离。

## 六、质量与性能需求

| 指标维度 | 建议基线要求 | 备注 |
|---|---|---|
| 伴学界面启动耗时 | 冷启动首屏 < 1.5s，任务间切换 < 300ms | 保证进入专注状态无卡顿 |
| OCR 与题目图文解析耗时 | P90 < 2.5s，P99 < 4.0s | 云端多模态大模型视觉解析 |
| 启发式问答首字流式响应（TTFT） | 纯文字/语音提问 P90 < 1.2s；图片提问 P90 < 2.0s | 流式输出，消除等待焦虑 |
| 语音转写准确率（WER） | 中小学生普通话识别准确率 > 93% | 适配童声语调与语速 |
| 提示阶梯遵循率 | 评测集上首轮拒绝给答案并给出有效引导的合规率 > 98% | Prompt 与安全规则强约束 |
| 本地状态暂存可靠性 | 异常退出、闪退或断网时，伴学计时与当前问答草稿 100% 可恢复 | 本地 SQLite/KV 自动持久化 |
| 崩溃率（Crash Rate） | 客户端伴学模块崩溃率 < 0.05% | 关键页面高稳定性保障 |

## 七、合规与隐私约束

1. **未成年人隐私强保护**：Ward 提问时上传的题目切图与问答对话属于未成年人个人信息，严格执行租户与家庭隔离，禁止公开泄露；
2. **音频数据最小化留存**：语音提问的音频流仅在内存中做即时转写，转写完成后原始音频切片在 24 小时内销毁，不长期落盘存储；
3. **第三方大模型数据脱敏**：调用公有云 LLM/VLM 接口前，客户端及服务端必须过滤并脱敏照片中可能包含的学校名称、学生手写姓名、家庭住址等 PII 敏感信息；
4. **版权与教材合规**：AI 生成的例题与解析应基于开源知识库与公有领域知识，避免成段侵犯第三方商用教辅版权；
5. **数据可删除权**：Guardian 或 Ward 发起注销或删除时，伴学历史提问记录必须完全从 OSS 及数据库中物理擦除。

## 九、团队与研发约束

- **前后端分工**：
  - `duxue-app`（Flutter）：负责伴学工作台计时、多模态输入组件（相机裁剪、语音录制振幅动画）、流式 Markdown/LaTeX 渲染与本地状态容灾；
  - `duxue-server`（FastAPI）：负责多模态题目解析路由、Prompt 支架编排（LangChain/自研 Agent）、内容安全过滤、知识点标签打标与复盘数据入库；
- **Prompt 质量与评测集要求**：
  - 研发必须构建覆盖语/数/英/物/化 5 大学科、至少 300 道典型题型的“启发式问答评测黄金集（Golden Dataset）”；
  - 每次 Prompt 或模型版本迭代，必须自动化运行评测集，确保“不直接给答案率”保持在 98% 以上；
- **多端一致性**：伴学工作台任务状态必须与 `prd-schedule.md` 中的计划状态机保持强一致。

## 十一、里程碑建议

1. **阶段一：需求与 Prompt 原型评审（Day 1~3）**：明确多模态交互形式、提示阶梯（L1~L4）判定规则、黄金评测集标准；
2. **阶段二：伴学工作台与核心答疑链路贯通（Day 4~10）**：实现 Flutter 伴学工作台、OCR 接入、流式启发式问答与安全拦截网关；
3. **阶段三：兴趣信号分流与任务收尾结算（Day 11~15）**：实现兴趣提问识别与沉淀、任务轻量收尾结算面板及多任务无缝流转闭环；
4. **阶段四：自用测试与评测集调优（Day 16~20）**：在真实中小学题目集上调优提示词，确保不出现直接泄露答案、误判兴趣等 Badcase；
5. **阶段五：复盘数据链路串联（Day 21+）**：与 ④ 结果评估（5.6）模块打通，完成完整伴学闭环。
