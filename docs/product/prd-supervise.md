# 学习观察与行为采集 PRD

> 更新日期：2026-11-01；产品路线已确定，标准摄像头网关待实现。旧 Android 手机采集程序已移除。
> 关联：[产品架构](ARCHITECTURE.md) · [采集技术设计](../technical/design-gateway.md) · [操作手册](../camera-setup-guide.md)

## 一、目标与边界

观察线下纸质作业过程，为晚间伴学实况单提供客观证据。孩子无需先建计划或点击学习开始/结束；在已启用的观察时段采集，云端自动还原学段的能力需单独验证。

采用每工位一个标准网络摄像头、每场地一个共享采集网关。家庭先用一台摄像头与同网电脑验证；机构试点使用预配置常开网关；家庭免网关方案后续通过成熟厂商固件适配实现。

摄像头负责提供图像，网关负责采集、缓存和上传，云端负责语义分析与报告。不得要求家长维护专用手机应用。协议、技术栈、接口和容量规则只在采集技术设计维护。

## 二、体验要求

- 侧后方约 45° 固定机位覆盖桌面与双手，尽量规避正脸；不能据此宣称画面已匿名化。
- 默认稀疏观察，管理者配置观察时段；孩子知晓采集状态并能现场暂停或停止。
- 不向 Guardian/Coach 提供实时监控流，不采环境音频，不用分心红字、扣分或蜂鸣打扰孩子。
- 初次配置包含配网、绑定学生、现场取景校准；日常无须重复绑定。
- Guardian 查看接入状态和晚间报告。机构摄像头绑定、Coach 授权及换座需要显式权限，不能跨学生混用证据。

## 三、可靠性与数据要求

- 外网中断但局域网正常时继续采集，恢复后补传；摄像头或局域网不可用时明确记录缺口。
- 上传失败不能阻塞采集；重启后恢复持久队列，重试不能生成重复证据。
- 记录采集时刻和当时归属，不能用上传时刻或当前座位学生重写历史证据。
- 区分网关云端连通与摄像头采集健康；当前设备心跳只支持前者，详细状态尚待实现。
- 不保存完整视频，不依赖云录像套餐或摄像头存储卡；图像留存、删除与授权遵循全系统数据治理约定。
- 稀疏视觉对动笔、思考与卡壳的辨识度需实测，报告应呈现证据覆盖和不确定性，不能把采集缺口算作不专注。

## 四、验收与非目标

采集最小实验与故障恢复验收统一见 [技术验收清单](../technical/design-gateway.md#五最小实验与验收)。采集成功不等于自动会话分段或行为判断已经达标；后两者须用标注样本与真实晚间场景验证。

本期不做自研摄像头硬件、本地行为模型、全品牌自动兼容、摄像头历史录像回取或远程实时监控。网关批量部署和远程运维在单机实验通过后推进。
