## 一、文档目标

本文档定义 `duxue-app` 中与用户直接相关的产品能力，包括：

1. 登录前角色选择；
2. Guardian 与 Ward 的登录方式；
3. 登录态与登录方式记录；
4. Guardian-Ward 家庭关系的绑定码关联；
5. Ward 和 Guardian 登录后的首页导航。

本文档不设计通用设备管理能力。除 Ward 主动进入“采集督查”模式外，不包含设备在线状态、电量、网络、存储、故障诊断或远程控制等设备功能。

## 二、产品原则

### 2.1 先选择角色，再完成登录

用户打开 App 后，先声明本次希望以 Ward 或 Guardian 身份进入，再展示对应登录页面。角色选择决定登录后的体验，但不直接授予权限；登录成功后，服务端仍需验证该账号确实拥有所选角色。

### 2.2 同一个 App，两套不同的首页逻辑

- Ward 首页回答：**我今天准备怎么行动？**
- Guardian 首页回答：**孩子最近发生了什么，我怎样才能更好地理解和支持他？**

两端可以使用相同的底层数据，但不能只替换角色名称后复用同一套首页。

### 2.3 Guardian 的核心任务不是“处理待办”

Guardian 使用产品的主要目的依次是：

1. 直接阅读孩子的学习报告，了解发生了什么；
2. 回看引导与孩子的推导，理解思考过程；
3. 根据报告判断是否需要介入；
4. 按需查看历史与长期变化。

学校作业输入只是“传递信息”的一种具体场景，不应成为 Guardian 首页和导航的中心。

### 2.4 采集与交互物理分离

桌面行为观察由标准摄像头与共享采集网关（读学Eye）承担，不内置在 `duxue-app` 的 Ward 端界面中。观察期间须明确采集状态，允许 Ward 现场暂停或结束；Go网关已实现，真实设备/OSS现场验收待完成，见 [采集设计](../technical/design-gateway.md)。

## 三、角色与关系模型

### 3.1 核心对象

| 对象 | 含义 |
|------|------|
| User | 登录系统的自然人账号 |
| Role | 用户本次进入 App 时使用的 Ward 或 Guardian（含共管伴学师 Coach）身份 |
| Family | Guardian 与一个或多个 Ward 所属的家庭/督学空间 |
| Membership | 用户在家庭/空间中的成员身份及权限 |
| Guardian-Ward Relationship | Guardian/Coach 与 Ward 的监护/伴学关系 |
| Login Session | 当前角色、登录方式和有效登录态 |
| Binding Code | Guardian 为 Ward 生成的一次性 6 位数字绑定码 |

### 3.2 角色选择与权限

角色选择是登录意图，不是权限来源。

- 用户选择 Guardian 后，只能进入 Guardian 登录流程；
- 用户选择 Ward 后，只能进入 Ward 登录流程；
- 登录成功后，服务端必须校验账号是否拥有所选角色；
- 校验失败时不得进入对应首页；
- 如果一个账号确实拥有多个角色，可以退出当前角色后重新选择角色登录；
- 不提供在已登录页面中无校验地直接切换权限的能力。

### 3.3 Guardian-Ward 关系、多监护人共管与 B2C 伴学师（Coach）场景

- **1 对多学生管理（赋能家庭多孩与 B2C 晚托班/伴学工作室）**：
  - 一个 Guardian / Coach 账号可以关联多个 Ward（支持 1~100 名学生快速切换与检索）；
  - 在精品晚托班、社区自习室或伴学工作室场景下，伴学老师（Coach）可通过共管授权同时管理班内 10~15+ 名学生，在单一工作台掌握全场学习动态并向对应家长交付日报。
- **多对 1 共管协作**：
  - 一个 Ward 可以被多个 Guardian / Coach（支持 1~20 名监护人/伴学师）共同关注与管理（如父母共管、主理老师与助教共管）；
- **两种权限级别**：
  - `full`（完全管理）：可传递外部任务、查看计划、查收《伴学闭环实况单》与《独立解题凭证》；
  - `readonly`（只读权限）：仅可查看每日伴学实况单与解题凭证；
- Guardian / Coach 可以在首页顶部快速切换当前查看的 Ward；
- Ward 登录后只进入自己的专属空间，不能切换查看其他 Ward。

## 四、登录与登录态

### 4.1 登录前角色选择页

App 冷启动且没有有效登录态时，首先显示角色选择：

```text
欢迎使用读学

你希望以什么身份进入？

[我是孩子]
[我是家长]
```

页面要求：

- 用简单语言说明两种角色的差异；
- 记住用户上一次选择的角色；
- 不展示手机号、生物识别等未支持方式；
- 已存在有效登录态时跳过该页面，直接恢复上次会话。

### 4.2 支持的登录方式

Guardian 使用**邮箱 + 一次性验证码**注册和登录，不设置或输入读学密码。每次登录都需要取得新的邮件验证码；验证码属于单因素邮箱登录，不能表述为双因素认证。

验证码由读学服务端生成并验证，10 分钟有效、仅可使用一次；重发后旧码失效。发送间隔至少 60 秒，每个验证码最多尝试 5 次；服务端还应按邮箱和请求来源限流。只有成功兑换验证码后才发放登录态。邮件送达不能证明持有某台特定设备，不能把邮件验证码当作独立的第二因素。

微信登录作为 Guardian 的后续便捷登录方式，须在微信开放平台的移动应用资质、权限和审核明确可用后接入。已有 Guardian 先通过原账号登录，再主动绑定微信身份；不得凭微信昵称或未验证邮箱自动合并账号。微信接入不改变服务端的 Guardian-Ward 授权关系。iOS 上线前还须核对 App Store 对第三方登录等效选项的要求。

Ward 目前通过 Guardian 发放的一次性绑定码进入；Ward 的其他登录方式需单独设计。当前不提供手机号验证码、游客登录或其他第三方登录。

### 4.3 Guardian 登录

Guardian 选择角色后进入 Guardian 登录页：

```text
家长登录

邮箱
[获取验证码]
6 位验证码
[登录]

[没有账号？注册]
```

注册流程：输入邮箱及显示名称 → 请求邮箱验证码 → 输入验证码 → 创建账号并登录。读学服务端生成并校验验证码；SMTP 服务只负责邮件投递。邮件发送失败或验证码无效时不得创建账号或发放登录态。当前测试账号数据无需迁移。

微信登录获批并实现后，可在此页增加“使用微信登录”；发布前不得展示不可用入口。

首次登录成功后：

1. 如果尚未加入家庭，引导创建家庭；
2. 创建或补充第一个 Ward 档案；
3. 生成 Ward 登录所需的 6 位绑定码；
4. 完成后进入 Guardian 首页。

### 4.4 Ward 登录

Ward 选择角色后进入 Ward 绑定页：

```text
学生登录

家长提供的 6 位绑定码
[绑定并进入]
```

Ward 当前通过 Guardian 发放的一次性绑定码进入学习空间，后续由客户端保存并刷新 Ward 会话；尚无 Ward 用户名密码或微信登录。

### 4.5 登录态记录

登录成功后，客户端记录：

- 当前用户 ID；
- 当前角色；
- 登录方式：Guardian 为 `email_code`，Ward 为 `invite_code`；Guardian 微信接入后可为 `wechat`；
- 当前家庭 ID；
- Guardian 当前选中的 Ward ID；
- 登录时间和最后活跃时间；
- Session/Token 及过期时间。

客户端不得记录：

- 邮箱验证码明文或持久化副本；
- 微信访问凭据明文；
- 可用于绕过服务端鉴权的角色标记。

### 4.6 登录态恢复

- 登录态有效：恢复上次角色并直接进入对应首页；
- 登录态过期：默认展示上次角色及上次使用的登录方式；
- 用户主动退出：清除登录态，但可以保留上次角色和登录方式；
- 服务端撤销会话：客户端收到鉴权失败后返回登录页；
- 当前角色不再有效：说明原因，不得继续展示已缓存的角色数据。

## 五、Guardian-Ward 绑定

### 5.1 Guardian 生成绑定码

Guardian 创建 Ward 档案后，可以生成一个一次性 6 位数字绑定码。绑定码关联：

- 当前家庭；
- 对应 Ward 档案；
- 发起 Guardian；
- 有效期限；
- 单次使用状态。

示例：

```text
孩子加入码

482731

请让孩子在登录页输入此绑定码
```

绑定码短时有效、仅能成功使用一次；应限制连续输错次数与请求频率，避免被批量猜测。

### 5.2 Ward 输入绑定码

Ward 在登录前选择“我是孩子”，进入学生登录页后输入 Guardian 提供的 6 位绑定码。

匹配成功后显示：

```text
你将加入：

家庭：小宇的家庭
家长：林女士
你的档案：小宇

[确认加入]
[取消]
```

Ward 确认后：

1. 建立 Ward 账号与 Ward 档案的关联；
2. 建立家庭成员关系；
3. 建立 Guardian-Ward 关系；
4. 使绑定码失效；
5. 完成登录并进入 Ward 首页。

### 5.3 异常处理

- 绑定码错误：提示检查后重试；
- 绑定码过期：提示 Guardian 重新生成；
- 绑定码已使用：不得重复建立关系；
- 连续输错达到限制：短暂禁止继续尝试；
- Ward 已绑定其他家庭：阻止自动覆盖；
- 登录账号角色不匹配：阻止绑定；
- 用户取消：不创建任何关系。

### 5.4 多 Guardian 共管邀请与成员管理 (Co-Guardian)

为满足家庭多监护人协作（如父母共管）及学伴/托管场景（如主老师与助教共管），系统提供轻量高效的“共管邀请与批量授权”机制，避免多监护人重复扫码。

#### 5.4.1 发起共管邀请与批量绑定
1. **主监护人发起**：主监护人在 App「我的 -> 共管成员 -> 邀请共管」中发起邀请：
   - **学生选择**：默认自动勾选名下全部 Ward，支持按需取消部分勾选（如请家教老师仅辅导大宝）；
   - **权限设定**：选择被邀请人的权限角色（`full 完全管理` 或 `readonly 仅看报告`）；
   - **凭证生成**：一键生成 6 位邀请码、二维码及微信分享短链（有效期 24 小时）；
2. **新监护人接受**：新监护人登录自身手机 App，点击扫码或输入 6 位邀请码（或在微信打开分享链接）：
   - 界面预览：展示“【XXX】邀请您共同关注【小宇、小涵】”；
   - 一键确认：点击「接受邀请」，系统底层一次性批量建立与所选全部学生的绑定关系，立即在首页展示所有关联孩子。

#### 5.4.2 后续新增学生自动同步（免重新扫码）
主监护人后续新增 Ward（如添加二宝档案）时：
- 创建表单底部提供轻量同步勾选项（默认勾选已有家人）：
  > “是否同步共享给已有共管成员？”  
  > `[✓] 爸爸 (完全管理)`  
  > `[  ] 数学家教 (只读)`
- 主监护人点击保存，系统在为本人创建绑定的同时，**自动为勾选的共管成员建立绑定**；
- 被同步成员打开自身 App 即可直接看到新学生，完全无需再次扫码或确认。

#### 5.4.3 共管成员管理与权限动态调整
主监护人可在「我的 -> 共管成员」中随时进行治理：
- **查看成员列表**：清晰查看每个共管成员姓名、手机号及当前管辖的学生名单；
- **动态增减学生**：随时勾选/取消勾选某成员对特定学生的管辖权；
- **调整权限等级**：在 `full` 与 `readonly` 之间平滑切换；
- **一键解绑移出**：支持单向解除与某监护人的共管绑定关系。

## 六、Ward 首页与导航架构（默认安静首页 + 按需对话 + 可选专注挑战）

Ward 首页优先帮助孩子回到线下作业：默认安静，不自动展开历史对话、弹键盘、铺任务进度；底部复用既有唯一 `VoiceComposer`，保留ASR与拍照结构。普通plan/task仅按需辅助记事、梳理顺序和核对，不从旧安排猜当前任务。

### 6.1 默认主界面

```text
┌────────────────────────────────────────────┐
│ 读学                                  [⋯] │
│                                            │
│          先做手边的一小步                  │
│          有问题，随时找我。                │
│                                            │
│         [试一轮专注挑战]                   │
│                                            │
│       原有 VoiceComposer：ASR＋拍照         │
└────────────────────────────────────────────┘
```

“作业 / 历史对话 / 专注挑战 / 清空历史对话”收在右上更多菜单，不作为任务切换器。首页不放“继续上次对话”按钮；主动输入或从更多菜单查看历史时，仍恢复同一对话。相机直接打开，取消不弹对话；选好图片后保留原暂存、上传与发送步骤。普通主动提问/查看历史才展开对话，可主动收起；收起不清线程、草稿、历史或在途请求，迟到回复不重新弹起。回到前台不擅自展开对话。

### 6.2 专注挑战：口述、只读确认、明确开始

点击“试一轮专注挑战”后，首页提示“这轮想做什么，试多久？说给我听”，继续使用同一个底部ASR，不弹主题/分钟填写框，也不自动开始录音。

- 说“数学，先试二十分钟”：整理为只读 `数学 · 20分钟`，提供 `[开始本轮] [重新说]`。
- 只说“二十分钟”：整理为 `专注挑战 · 20分钟`，不追问主题、不猜历史作业。
- 只说“写数学”：只问“想试多久？”，下一句口述保留本轮明确主题；纠正以新口述为准，不要求重复全部内容。
- 重新说用于口述修正；“先不用”或明确口述取消都能返回安静首页。取消后，迟到ASR/整理结果不能变成普通聊天或重新弹确认。
- 整理阶段不创建任务、学习会话或挑战，不修改正在答疑的对话；合法时长且孩子点击“开始本轮”后才计时。语音识别/模型/开始失败可重试，不补默认20/30分钟。

只有本人主动开始、实际起点和正时长齐全的Sprint才显示弱计时卡，支持暂停、继续、结束本轮和收起。主题是本轮口述标签，不等于系统已知当前Task；到时只结束本轮计时，不代表作业完成或成功专注，不切下一项。已有active/paused轮次重新打开时恢复本轮，不重复开新轮。完整时间与运行语义归 [计划 PRD §4.4](prd-schedule.md#44-专注挑战sprint)。

### 6.3 按需查看与统一对话

答疑界面提供安静的专注挑战图标，复用同一ASR与独立只读预览；取消或开始后保留原对话、草稿与原题，不跳回首页。收起对话同时取消未确认的预览，迟到结果不重开。自然语言提出挑战仍走受控Study动作；从答疑临时进入挑战后，继续答疑恢复原暂停Run，不创建新的原题上下文。

- 更多菜单的“作业”或主动询问“今天还有什么”才展示全部已知事项；未知进度不假定为未做，不要求孩子维护状态。
- 普通任务执行、顺序调整和用时查询继续按需操作；安排确认卡只出现在相关对话，历史卡留在原处。
- 底部组件仍是唯一AI输入：普通请求走Companion的planning/tutoring/reflection；挑战口述使用Study的独立只读整理，开始/暂停/结束交给Study。技术契约归 [Study](../technical/domain-study.md#24-sprint主动专注挑战已实现待验收)。
- 保留原LaTeX、配图、发音、历史分页与看图；清空可见历史不删除领域事实。主动邀请边界仍归 [计划 PRD §3.4](prd-schedule.md#34-主动引导的边界)，不在答疑中插话。

## 七、Guardian / Coach 首页导航

Guardian（家长）与 Coach（晚托班/督学伴学师）使用产品的主要目标是：**从书桌旁彻底解放出来，每晚高效查收确定性的伴学闭环结果，并按需传递外部作业信息。**

### 7.1 核心首页：报告直接呈现

默认进入「报告」，底部导航为「报告 / 孩子 / 我的」。首页只有两个内容区，优先让家长阅读已有证据，不要求说话、录音、导入作业或催孩子总结。

1. **学习报告直接展开**：显示所选孩子、所选日期的已有报告正文与观察过程，不再提供“查看完整报告”二次跳转，不放饼图、份数/次数统计或独立“可能需要支持”卡片。需要家长关注的事实由报告正文表达，不制造额外待办。
2. **独立解题凭证**：有逐题引导和孩子后续实质尝试时展示题目，可就地展开真实引导与回应；不显示几份几次，不把“提交答案”或“我懂了”当作已通过核验。没有凭证时不占位；报告尚未生成也不阻塞已有凭证。完整教学证据语义见 [评估 PRD](prd-evaluate.md#213-独立解题凭证核心内容兑现-p0-3)。

顶部可切换孩子，通过安静的「历史」日期入口查阅往日；下拉刷新及回到前台重新读取。切换孩子、日期时，不展示另一孩子或另一日期的旧内容。

**未生成与异常状态**：没有当日报告时显示“报告尚未生成”，正在处理显示“正在整理学习报告”；加载失败单独显示错误与重试，不伪装成没有记录，也不编造报告。凭证失败只影响凭证区。报告不以孩子完成今日总结为前提。

> **实现范围**：本轮直接展示已有观察日报，并补齐逐题推导记录查询；完整证据版本化报告引擎仍见 [Evaluation](../technical/domain-evaluation.md)，不能把当前记录页宣称为已完成该引擎。页面不展示实时摄像头，不提供修改孩子已确认计划的入口。

### 7.2 作业传递降为次级操作

作业传递仅保留在「孩子」页各孩子的操作菜单中，支持偶尔转入学校作业文字或图片；不再在报告页或孩子列表底部放常驻输入/录音框，不提供独立留言产品能力。

任务候选、来源与可选安排规则统一见 [计划 PRD](prd-schedule.md)。未传递作业不影响伴学与报告阅读。
