## 一、背景与定位

### 1.1 系统定位

在读学系统中，记忆系统（产品架构中定义为 **“孩子理解引擎 / Child Understanding Engine”**）是整个五场景产品闭环背后的**“长期记忆中枢与智能底座”**。

它不直接面向学生提供独立的业务操作界面，而是作为一个纯系统级能力（System Capability），跨时段、跨场景地感知、抽取、整合与维护对学生（Ward）及家庭互动模式的结构化理解，并按需向各个前台业务模块（协商计划、伴学执行、结果评估、深度引导）注入精准的上下文记忆（Context Injection）。

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        业务前台交互层 (Client UI)                       │
│  ② 协商计划 (prd-schedule) │ ③ 伴学执行 (prd-companion) │ ④ 结果评估 (prd-evaluate) │
└─────────────┬──────────────────────────┬─────────────────────────┬─────┘
              │ 产生交互事件              │ 产生提问/卡点            │ 产生自评/对比事实
              ▼                          ▼                         ▼

│             孩子理解引擎与记忆系统 (prd-memory.md / 纯系统能力)          │

│  ┌──────────────────────────────────────────────────────────────────┐  │

│  │ 3. 长期人物画像 (Long-Term Persona & Semantic Profile)           │  │
│  │    - 专注耐力基线 · 学科思维模式 · 持续兴趣图谱 · 亲子沟通偏好   │  │
│  └──────────────────────────────────────────────────────────────────┘  │

┌────────────────────────────────────────────────────────────────────────┐
│                        业务模块消费与呈现 (Consumers)                   │
│  → 注入 ② 协商计划：提供历史时长基线校准、智能推荐微休息与任务拆解     │
│  → 注入 ③ 伴学执行：基于学生理解层次分步答疑、识别兴趣发散             │
│  → 注入 ④ 结果评估：提供 5 天基线对比、难题攻坚归因、驱动成长趋势展示   │
│  → 注入 ⑤ 深度引导：生成定制化兴趣探索小径、家长睡前正向沟通建议       │
```

### 1.2 模块边界与呈现原则（严格解耦）

1. **纯系统底座，无学生端独立 UI**：
   - 记忆模块本身**坚决不向学生展示独立的“记忆列表”或“模型参数看板”**，避免增加认知负担或让孩子产生“被系统定性打标”的心理压力；
2. **所有可视化呈现均归属业务模块（Evaluate / Explore 等）**：
   - **兴趣图谱与探索地图**：由 `prd-explore.md`（深度引导/兴趣探索）消费长期画像数据并负责可视化展示与探索路径分发；
   - **自主度趋势、专注力耐力变化折线、复盘成长趋势**：由 `prd-evaluate.md`（结果评估）消费近 5 天事件记忆与长期基线并负责双端呈现；
   - **自评对比与今日发现**：由 `prd-evaluate.md` 结合当日工作记忆与近期基线即时生成。
3. **透明可控的底线合规管理**：
   - 仅在 Guardian 端 **【设置 / 隐私与数据管理】** 中提供合规看板，允许家长查看系统记录的客观属性画像，并支持监护人依法行使“一键清除/被遗忘权”。

### 1.3 核心设计原则

1. **客观事实优先，拒绝道德定性**：
   - 记忆存储的是“19:35~19:47 手部离开桌面”“数学多步骤应用题 L3 提示后解出”等客观事实，严禁存储“磨蹭、懒惰、笨拙”等主观定性标签；
2. **动态成长自适应（时间衰减与演进）**：
   - 孩子处于快速身心发育期，历史上的“易分心”或“某题型薄弱”具备时间半衰期（Half-life）。随着近期表现改善，旧标签自动淡化，避免给孩子贴上永久标签；
3. **分层分级存储，按需精准召回**：
   - 短期重在**实时连贯**，近期重在**情境事实**，长期重在**稳定规律**。大模型交互时按需召回相关上下文，避免冗余 Prompt 污染。

## 二、三层记忆模型架构（Three-Tier Architecture）

系统将记忆结构化解耦为三层，各层具备明确的生命周期与数据职责：

```text
┌────────────────────────────────────────────────────────────────────────┐
│ 1. 短期工作记忆 (Working Memory) · 生命周期：任务/会话级 (分~小时)     │
│    - 当前正在执行的任务信息（学科、计划用时、已执行时长、当前状态）    │
│    - 本次任务内的多轮 AI 启发问答会话上下文（题干图文、L1~L4 提示阶梯）│
│    - 临时卡壳点、草稿暂存、当次任务捕获的临时好奇心提问                │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ 任务完成 / 会话结束时归档沉淀
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 2. 近期事件记忆 (Recent Episodic Memory) · 生命周期：滚动近 5 天 (滑动窗口) │
│    - 近 5 天任务流水：每日完成的具体作业清单、实际耗时 vs 预估偏差    │
│    - 近 5 天学科疑问明细：遇到的具体题目题型、知识点标签、卡壳停留时长 │
│    - 近 5 天自评与行为事实：盲评状态、客观动作时间轴、沉淀的专注锦囊  │
│    - 近 5 天好奇心信号池：孩子发散提问的主题原始记录（未成熟信号）     │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ 达到频次阈值 / 周期性聚类提炼
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 3. 长期人物画像 (Long-Term Persona Profile) · 生命周期：跨周期演进 (周~月) │
│    - 专注耐力与节奏基线：各学科的平均有效心流时长、高发疲劳拐点       │
│    - 学科认知与思维模式：已攻克/反复卡壳的知识点图谱、启发敏感度偏好  │
│    - 持续兴趣主题图谱：跨天数、多频次出现的兴趣领域（如昆虫、天文学）  │
│    - 自主规划成熟度：自主发起计划占比、任务预估时间校准系数            │
│    - 家庭互动与沟通偏好：家长有效正向鼓励模式、焦虑易发情境特征       │
└────────────────────────────────────────────────────────────────────────┘
```

### 2.1 第一层：短期工作记忆（Working Memory）

- **定义与作用**：支撑当前单次学习会话（Session）的实时连贯交互。
- **存储载体**：Redis 缓存 + 客户端本地 SQLite 暂存（保障断网不丢）。
- **生命周期**：当前任务执行期间（分钟至数小时）；任务完成或主动退出后，关键数据抽取至第二层，工作缓存释放。
- **核心数据结构**：
  ```json
  {
    "session_id": "sess_20260817_001",
    "ward_id": "ward_101",
    "current_task": {
      "task_id": "task_math_01",
      "subject": "math",
      "title": "数学练习册 P23-25",
      "planned_minutes": 45,
      "elapsed_seconds": 1455,
      "status": "in_progress"
    },
    "current_dialogue": [
      {
        "turn_id": 1,
        "input_type": "image_crop",
        "ocr_text": "鸡兔同笼，共有头10个，脚28只...",
        "knowledge_tag": "math_simultaneous_equations",
        "current_hint_level": "L2",
        "ai_response": "太棒了！如果我们假设这 10 只全都是鸡...",
        "user_state": "thinking"
      }
    ],
    "transient_signals": [
      { "type": "curiosity", "query": "蚂蚁为什么能认路", "timestamp": "2026-08-17T19:20:15" }
    ]
  }
  ```

### 2.2 第二层：近期事件记忆（Recent Episodic Memory · 滚动近 5 天）

- **定义与作用**：记录 Ward 近 5 天内真实发生的具体学习事实情境，作为近期排期参考、即时复盘对比和连贯答疑的依据。
- **存储载体**：PostgreSQL 关系数据库（带时序索引）。
- **生命周期**：滑动窗口保留最近 5 天（T-4 ~ T 日）；超出 5 天的数据经聚合蒸馏后进入长期画像，原始流水转冷存储或按留存策略脱敏归档。
- **核心数据包含**：
  1. **任务与时长流水**：近 5 天每天完成了哪些作业、各学科实际耗时、预估准确度；
  2. **学科卡点与答疑记录**：近 5 天遇到的具体题目、识别出的知识点、经历的提示阶梯、是否独立解决；
  3. **自评与事实记录**：近 5 天每天的自我主观评价、客观行为动作区间（读写/调整/发呆）、收录的“专注锦囊”；
  4. **未成熟兴趣信号流水**：近 5 天偶发提出的课外问题（如“恐龙灭绝”“太阳黑子”）。

### 2.3 第三层：长期人物画像（Long-Term Persona & Semantic Profile）

- **定义与作用**：跨周期的稳定认知与规律模型，体现孩子的成长基线与行为偏好。
- **存储载体**：PostgreSQL JSONB + 结构化特征向量。
- **生命周期**：长期动态维护，结合时间衰减函数持续演进更新。
- **核心维度定义**：

| 画像维度 | 具体字段与度量 | 业务反哺应用场景 |
|---|---|---|
| **专注耐力基线** | 各学科平均心流时长（如数学 18m、英语 30m）、疲劳拐点时间分布 | 注入 ② 协商计划推荐微休息；注入 ④ 结果评估做疲劳归因 |
| **学科认知特征** | 各知识点掌握度（自主攻克/需L4解析/待问老师）、偏好的启发风格 | 注入 ③ 伴学答疑，动态调整首轮引导的步长与抽象度 |
| **持续兴趣图谱** | 经过 5 天滑动窗口聚合验证的高频兴趣领域（领域标签、信号出现频次、持续天数） | 注入 ⑤ 深度引导生成定制化探索小径（如蚂蚁观察任务） |
| **自主规划成熟度** | 任务预估偏差校准系数（如预估通常偏短 30%）、孩子自主发起任务占比 | 注入 ② 协商计划生成更合理的 AI 计划草稿 |
| **家庭互动特征** | 家长焦虑触发情境特征、正向鼓励的有效切入点（如肯定独立解题过程） | 注入 ④ 结果评估生成当晚家长睡前亲子沟通建议 |

## 三、记忆生命周期与处理管道

理解引擎通过自动化后台流水线（Pipeline）完成记忆的流转与演进：

```text
┌─────────────────┐
│ ① 业务事件输入   │ (计划确认 / 任务结束 / 答疑完成 / 复盘提交)
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ ② 结构化抽取     │ 提取事实实体 (Subject, Knowledge_Tag, Duration, Signal_Type)
│  (Fact Extractor)│
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ ③ 写入近期事件   │ 写入近 5 天滚动流水 (Episodic Store)
└────────┬────────┘
         │
         ▼ (异步批处理 / 会话结算时触发)
┌─────────────────┐
│ ④ 整合与模式提炼 │ 运行聚类与置信度算法 (Consolidation Engine)
│  (Consolidation)│ - 频次与跨度校验 (如: 5天内出现 >= 2次 ──▶ 晋升为成熟兴趣主题)
└────────┬────────┘ - 基线统计更新 (如: 重新计算数学平均专注耐力)
         │
         ▼
┌─────────────────┐
│ ⑤ 衰减与演进更新 │ 历史弱项标签施加时间半衰期衰减 (Half-Life Decay)
│ (Decay & Update)│ 新证据覆盖旧偏差，消除冲突
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ ⑥ 上下文动态召回 │ 根据调用方需求 (计划/答疑/复盘)，组装语义 Context 并注入 Prompt
│(Context Injector)│
└─────────────────┘
```

### 3.1 兴趣信号晋升机制（Interest Signal Promotion）

为了防止“随口一问”被过度解读，系统建立严格的从临时信号到长期兴趣主题的晋升门槛：
- **阶段 1（临时信号）**：Ward 提出课外好奇心问题，存入短期工作记忆并在结算后落入近 5 天事件记忆，此时**仅记录不建档**；
- **阶段 2（候选兴趣）**：近 5 天内同领域信号出现 2 次以上，或者单次提问展现极高探究深度（多轮追问），标记为 `Candidate_Topic`；
- **阶段 3（成熟兴趣主题）**：跨越 2 次及以上独立学习会话，系统在长期画像中建立正式的 `Interest_Topic`，触发 ⑤ 深度引导模块为其生成结构化探索路径。

### 3.2 动态衰减与成长演进机制（Decay & Evolution）

- **弱项标签的自动淡化**：若某个知识点卡点或“易分心”模式在最近 14 天内未再次出现，且近期同类任务表现良好，该特征权重自动衰减至归零；
- **校准系数动态平滑**：预估时间校准系数采用指数移动加权平均（EMA），赋予近 5 天数据更高权重，灵敏反映孩子近期的自制力进步。

| **④ 结果评估** (`prd-evaluate.md`) | 今日学习结束、Ward 提交自评后 | 当日客观行为事实、近 5 天自评吻合度基线、答疑卡点记录 | 驱动双轨对比视图呈现、完成根因归因、生成个性化锦囊，并向家长端推送沟通话术 |

## 五、合规、安全与隐私管理

### 5.1 未成年人数据保护原则

1. **去人格化与去诊断化约束**：
   - 理解引擎内**严禁生成任何心理学或精神医学临床诊断性结论**（如“注意力缺陷”“多动障碍”）；
   - 严禁生成侮辱性、贬低性或永久性负面性格标签（如“笨拙”“磨蹭”）；
2. **严格租户与家庭物理隔离**：
   - 记忆数据库强制注入 `tenant_id` 与 `family_id` 过滤，严禁跨家庭进行记忆串扰或未经脱敏的横向比较。

### 5.2 Guardian 侧透明看板与被遗忘权（Right to be Forgotten）

虽然学生端不展示底层记忆，但为满足法律合规与监护人知情权，系统在 Guardian 端 **【我的 → 隐私与数据管理】** 提供管理能力：

1. **记忆透明度查看**：
   - 家长可查看系统当前记录的孩子客观学习偏好摘要（如：“常学科目：小学数学；近期探索主题：自然生物；平均专注节奏：25分钟”）；
2. **记忆选择性擦除与重置**：
   - 支持家长发起“清空历史兴趣记录”“重置学习习惯模型”或“注销账号物理删除所有历史数据”；
   - 指令下发后，服务端在 24 小时内物理擦除数据库与向量索引中的相关数据。
