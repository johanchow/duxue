## 一、方案选择

| 方案 | 硬件成本 | 当前状态 | 说明 |
|------|---------|---------|------|
| **A. 闲置 Android 手机** | 0（已有） | ✅ **已支持，唯一推荐** | 安装读学Eye 即可，定时抓拍上传 |
| B. 专业 IP 摄像头 | ¥150~300 | ⏳ 暂未开放 | 需要服务端增加拉流抓帧能力，且依赖尚未建设的 Admin 后台 |
| C. 萤石摄像头（开放平台） | ¥100~200 | ⏳ 暂未开放 | 同上，且视频流会经过萤石云 |
| D. USB 摄像头 | ¥100~350 | ✖ 不考虑 | 需要电脑常开 |
| E. 自制 ESP32-CAM | ¥30~50 | ✖ 不考虑 | 需硬件开发 |

**当前阶段只支持方案 A。** 方案 B / C 的接入流程依赖读学 Admin 后台（填写摄像头凭证、查看接入配置），而 Admin Web 尚未建设。这两个方案的操作指南保留在 §三、§四 作为后续实现的设计参考，但**现在无法使用**。

## 二、机位指引（重要）

机位直接决定识别准确率，也决定隐私边界。**推荐机位：被观察者侧后方约 45°、略高于头顶俯拍。**

```
        俯视示意
                  ┌──────────┐
                  │   桌面    │
                  │  书本/笔  │
                  └────┬─────┘
                    [ward]
                      │
                 45° ╱
                    ╱
              [手机]  ← 侧后方，略高于头顶
```

取景框应覆盖：**桌面、双手、上半身、头部轮廓**。不需要拍到正脸。

**为什么是这个角度：**

系统判断行为主要依据三项信息，这个角度全部能看清：

| 信息 | 判别价值 | 这个角度能否看清 |
|------|---------|---------------|
| 手在干什么（握笔 / 翻书 / 玩东西 / 拿手机） | 最高 | 能 |
| 桌面有什么（书本 vs 手机 vs 玩具） | 最高 | 能，俯拍视角最清楚 |
| 头朝哪里（低头朝桌面 vs 转向侧方） | 中 | 能，头部朝向不需要看到正脸 |

同时因为看不到面部特征，天然满足隐私要求——送往 AI 服务的图片不含可识别面部信息。

**需要接受的一个能力损失：** 这个角度下"睁着眼发呆"和"低头看书"无法可靠区分——两者的头部朝向、手部状态、桌面物品可能完全一致。系统会尽量用"长时间完全静止"作为补充线索（真在阅读的人会翻页、会移动手），但这类判断的准确率低于其他行为。

**要避免的机位：**

- 正对面部拍摄——会采集到可识别面部信息，且看不清桌面
- 纯俯拍桌面（不含人）——看不到头部朝向和身体姿态，无法区分"离开"和"趴着"
- 距离过远——手部动作和桌面物品分辨不清，这两项恰恰是判别度最高的信号

## 三、方案 A：Android 手机（最推荐）

### 原理

将一台闲置 Android 手机架设在 ward 场景附近，安装**读学Eye**（Cam App）后，手机每 15 秒自动拍摄一张照片并上传到读学服务器，服务器汇总当日照片后进行 AI 分析并生成报告。

**手机不推送视频流，只上传照片。** 这意味着：上行流量约 80 kbps（一小时约 35 MB），手机不需要持续视频编码因此耗电大幅降低，网络中断时照片会暂存在手机本地、恢复后自动补传不丢数据。

### 所需材料

- 闲置 Android 手机一部（Android 8.0 及以上）
- 手机支架或固定架（¥10~30），能固定在 §二 描述的侧后方 45° 位置
- USB 充电器（长期插电工作）
- 可以连接互联网的 WiFi 网络

### 操作步骤

**第一步：Guardian 在读学 App 中生成邀请码**

1. 打开读学 App，进入 ward 的档案页
2. 点击"添加摄像设备"
3. 系统生成一个 6 位邀请码和对应二维码（有效期内一次性使用）

**第二步：在手机上安装读学Eye（Cam App）**

在 Android 手机上安装**读学Eye**（应用商店搜索"读学Eye"，或扫描运营方提供的安装二维码下载）。

**第三步：关闭电池优化**

为确保 App 在后台长期稳定运行：

```
手机设置 → 电池 → 找到"读学Eye"App
→ 将电池优化设置为"无限制"或"不限制"
→ 同时开启"自启动"权限
```

**第四步：输入邀请码完成绑定**

1. 打开读学Eye，点击"扫码绑定"扫描第一步生成的二维码（或手动输入 6 位邀请码）
2. 邀请码有效期 10 分钟，过期需在读学App 中重新生成
3. 绑定成功后，App 会显示已关联的 ward 名称

**第五步：调整机位并开始监控**

1. 进入设置页，屏幕会显示取景预览和参考框
2. 按 §二 的指引把手机固定在侧后方 45°，调整到桌面、双手、头部轮廓都在框内
3. 返回监控页，点击"开始监控"

### 注意事项

- **供电**：手机必须插着充电器运行，长期运行仍会耗电
- **网络**：手机需要能访问互联网（连接 WiFi 即可，无需与服务器同一局域网）
- **锁屏**：读学Eye 支持锁屏后后台运行，但需确保已完成第三步的电池优化设置
- **开机后需手动恢复**：Android 新版本（14 及以上）禁止应用在开机时自动启动摄像头。手机重启后，读学Eye 会发一条通知，**需要点击该通知才能恢复监控**。这是系统限制，无法绕过
- **掉线会收到通知**：如果设备意外停止工作，guardian 会在 3 分钟内收到通知
- **摄像头被独占**：运行期间这台手机的摄像头无法被其他应用使用
- **iOS 不适用**：iPhone/iPad 系统限制后台摄像头访问，不适合长期挂机使用

## 四、方案 B / C：IP 摄像头（⏳ 暂未开放，设计参考）

> 以下两节是后续实现的设计参考，**当前无法使用**。

### 4.1 方案 B：专业 IP 摄像头

**适用场景**：需要更稳定、无人值守的长期部署，或需要在没有闲置手机的场所使用。

**推荐硬件**：

| 型号 | 价格 | 说明 |
|------|------|------|
| 海康威视 DS-2CD 系列（工程款） | ¥150~300 | 支持 ONVIF 协议，可彻底关闭云功能 |
| 大华 DH-IPC 系列 | ¥150~300 | 同类，企业级稳定性 |
| Reolink 系列 | ¥150~250 | 支持 RTMP 推送到自定义服务器 |

> **重要**：务必选"工程款/网络摄像头（NVR 用）"，而非"智能家居摄像头"（萤石/小米消费款）。消费款的云同步功能难以彻底关闭，无法满足自有服务器模式的隐私要求。

**操作步骤**：

1. **购买并开箱**：确认摄像头支持 RTMP 推流或 RTSP 拉流协议（产品参数页通常有注明）
2. **连接网络**：通过网线或 WiFi 将摄像头接入可以连接互联网的网络
3. **配置推流地址**：在摄像头的 Web 管理界面中找到"推流设置"或"视频输出"，填入读学服务器提供的接入地址
   > 具体地址格式待定：服务端当前不接收视频流，接入 IP 摄像头需要先实现"拉流 + 定时抓帧"模块。届时倾向由服务端主动拉 RTSP 流并按间隔抓帧，而非让摄像头推流——这样无需在服务端常驻流媒体组件。
4. **关闭云同步**（隐私保护）：在摄像头设置中，关闭所有云存储、远程访问相关功能，并通过路由器确认摄像头没有主动对外联网流量
5. **绑定设备**：与方案 A 的第五步相同，在读学 App 中为 ward 生成绑定二维码，完成设备绑定

### 4.2 方案 C：萤石摄像头（经萤石开放平台）

**适用场景**：guardian 已有萤石品牌摄像头，且接受视频流经过海康/萤石云服务器（知名大厂，guardian 已接受其隐私条款）。除方案 B 的相同限制外，本方案的视频流还会经过萤石云服务器，与系统的隐私定位有额外冲突，需要在产品层面单独评估。

**前置条件**：

1. 前往 [萤石开放平台](https://open.ys7.com) 注册开发者账号
2. 创建应用，获取 `AppKey` 和 `AppSecret`
3. 摄像头需绑定到该应用下（通过设备序列号+验证码）
4. 在萤石 App 的设备设置中**关闭视频加密**，否则拉流时需要额外传入验证码

**操作步骤**：

1. **获取萤石开发者凭证**：登录萤石开放平台 → 创建应用 → 记录 AppKey 和 AppSecret
2. **将摄像头绑定到应用**：在萤石开放平台控制台，通过设备序列号和验证码将摄像头关联到你的应用
3. **在读学系统后台填入凭证**：进入读学 Admin 后台 → 摄像接入配置 → 填入 AppKey、AppSecret 和设备序列号
4. **绑定设备**：与方案 A 的第五步相同，在读学 App 中为 ward 生成绑定二维码，完成设备绑定

**注意事项**：

- accessToken 有效期约 7 天，系统会自动刷新，无需手动操作
- 查看历史录像需要购买萤石云存储增值服务（额外付费）
- 商业规模化使用需购买萤石开放平台的 API 调用量资源包

## 五、常见问题

**Q：Android 手机锁屏后 App 停了怎么办？**

> 进入"设置 → 电池 → 应用电池管理"，将**读学Eye**设为"无限制"，并开启"自启动"权限。不同品牌手机的菜单位置略有差异（小米、华为、OPPO、vivo 的后台管理比原生 Android 更激进，务必完成这一步）。

**Q：手机重启后为什么不自动继续工作？**

> Android 14 及以上版本明确禁止应用在开机时自动启动摄像头，这是系统层面的限制，任何应用都无法绕过。读学Eye 会在开机后发一条通知，点击即可恢复监控。如果忘记点击，guardian 会在设备心跳超时 3 分钟后收到掉线通知。

**Q：手机如何连接到部署在云上的服务器？**

> 手机只需能正常连接互联网（连 WiFi 即可），无需与服务器在同一局域网。

**Q：网络不好或断网了，数据会丢吗？**

> 不会。照片会暂存在手机本地队列，网络恢复后按时间顺序自动补传。本地队列上限为 2000 张或 500 MB，超出后会丢弃最旧的照片。监控页会显示当前积压数量。

**Q：iOS（iPhone/iPad）能用吗？**

> iPhone 不支持后台持续访问摄像头。iPad（USB-C 接口，iPadOS 17+）理论上支持外接 UVC 摄像头，但挂机体验差且需要额外开发。**建议使用闲置 Android 设备**。

**Q：一个 ward 可以绑定多台摄像设备吗？**

> 支持。每台设备独立绑定，分别持有各自的设备凭证。guardian 可以在 App 中查看每台设备的在线状态。

**Q：萤石 API 可以接入小米摄像头吗？**

> 不能。萤石是海康威视旗下产品，有独立的开放平台。小米摄像头走米家 IoT 体系，官方没有面向开发者的公开视频流 API，接入难度大，不建议使用。
