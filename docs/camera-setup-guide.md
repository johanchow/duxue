# 摄像设备接入与家庭实验手册

> 更新：2026-11-01。标准摄像头 + 本地共享网关是当前路线；旧手机采集程序已移除。网关尚未实现，以下是准备和验收步骤，不代表现在已有可执行网关命令。
> 技术契约与验收唯一维护于 [采集设计](technical/design-gateway.md)。

## 一、准备设备

- 一台持续供电的网络摄像头，支持本地 ONVIF JPEG 快照或 RTSP；优先直接取 JPEG。
- 一台同局域网电脑，作为实验网关；无需购买 NVR、存储卡或云录像套餐。
- 电源适配器、可调支架和家庭 Wi-Fi；电脑与摄像头之间不能启用客户端隔离。
- 具体型号须确认本地账号、断外网仍可取图、视频编码、快照接口和重启恢复；型号、硬件版本、固件需留档。商品页写 ONVIF 不等于快照已验收。

## 二、配网与机位

1. 按厂商说明激活、配网并设置本地访问账号；必要时开启 ONVIF/RTSP。
2. 在路由器中保留摄像头地址，记录接口与凭证，凭证不提交仓库或写入日志。
3. 架在学生侧后方约 45°、略高于头顶的位置，覆盖桌面、双手与书本，尽量规避正脸。该角度不能保证图像匿名化。
4. 固定机位，关闭自动追踪、非必要云上传和音频；让孩子知晓观察时段与停止方法。
5. 在电脑验证本地快照或码流，包括断外网后的可用性。仅在现场进行取景校准，不向家长提供远程实时画面。

## 三、网关接入（待实现）

家庭验证采用人工配置：为每台摄像头填写稳定本地编号（如 `camera-01`）、RTSP/快照地址、摄像头本地账号引用及 `ward_id`。部署者为整个网关配置一次受限云端凭证，并在服务端授权对应 Ward；不使用绑定码或逐摄像头云端 Token。配置格式与身份规则唯一见 [采集设计 §4.1](technical/design-gateway.md#41-配置与身份契约)。首轮固定学生与工位，不测试换座。

网关每 15 秒取图，持久缓存后申请预签名 URL、直传 OSS、提交帧元数据。目标网关接口见 [采集设计 §4.5](technical/design-gateway.md#45-interface目标云端协议全部待实现)，尚需实现；[服务端设计 §7.2](technical/design-server.md#72-采集设备接入-devices--frames) 记录现有逐设备认证接口，不能直接当作新网关接口使用。服务端应配置真实 OSS 后端，本地文件存储不能代替 OSS 验收。

网关是主动采集上传程序，不需要向公网开放端口。网关实现后再补实际启动、配置与停止命令。

## 四、验证与故障边界

按 [采集验收清单](technical/design-gateway.md#五最小实验与验收) 验证连续 3 小时、外网中断补传、摄像头断电重连、网关进程重启和两台设备隔离。

外网断开但局域网正常：可以继续取图并缓存。摄像头断电或局域网断开：没有采集到的帧无法补回；本方案不读取摄像头存储卡中的历史录像。

云端心跳正常只证明网关可访问服务端，摄像头是否正常取图还需查看网关的最后成功采图时间与错误记录。
