# Ward 语音输入与答疑朗读

## 目标与验收

- [x] 孩子按住说话时看到连续修订的草稿，松手后只发送一次终稿。取消、超时、断连或已定稿一段后仍有尾句时，不允许静默发送截断的提问。
- [ ] 普通提问显示书面整理稿，导师能获得原始转写。数字、单位、否定、英文和表达不确定性的成分须在样本集里专项核查。今日总结的逐字引用与发音目标以未经润色的终稿为依据。原始录音仅在本轮内存中使用。
- [x] 普通答疑的正式 AI 气泡可点读、停止、重播。语音提问后的自动朗读由孩子开启，默认关闭。开始录音、离开页面或切换对话时停止播放，迟到的音频响应不能重新起播。
- [ ] 服务端根据已鉴权的 Ward 与正式消息引用取正文合成，发音卡继续点读已确认的词句。覆盖跨 Ward、学生消息、未审核草稿及空正文。验证教学语气、轻重音、中英混读及容易混淆的数学表达。
- [ ] 自动测试与真机、真实语音质量验收分别记录。比较新旧 ASR 的中文字符错误率、关键信息保真率和终稿 P90 延迟；TTS 记录首声 P90，以相同文本盲听 Flash 与 Plus。

## 实现计划（Gate 1）

1. 服务端 ASR：扩展 `app/infrastructure/ai/asr.py`、`api/v1/system.py` 和配置，适配 qwen-audio-3.1-asr-flash-message 的音频与句级修订协议，保留现有 provider 可选。先验证供应商能否同时返回原始与整理终稿；若只返回一种，以关闭润色的终稿为准，独立做文本整理，整理超时退回原始终稿。修正异常收尾，兼容已有客户端事件。
2. 输入链路：扩展 Flutter 的 VoiceTranscriptionService、VoiceComposer 与 Ward 对话提交；沿用统一意图路由，把原始转写传给需要逐字引用的业务，整理稿用于普通提问展示。复用现有 turn/message 元数据，核实历史消息回放。补协议与应用层测试。
3. 朗读服务：在 Companion 消息查询旁添加只读接口；按当前身份、消息归属及正式回复类型加载文本。新增可配置的 qwen-audio-3.1-tts-flash 适配器及教学朗读指令，对公式按可验证的支持范围处理。覆盖收发协议、鉴权、失败和历史正式消息。
4. App：在 day_story_pages.dart 的普通答复气泡接入播放控制，复用 SpeechPlayback，并让发音卡、录音入口和普通朗读共享停止逻辑。测试手动与自动播放、加载期间打断、切换页面和合成失败。
5. 更新 App/Server 设计、配置样例与领域笔记。运行服务端和 Flutter 回归、静态检查；真实童声样本及设备可用时进行对照，记录实测条件后提交 Gate 2 验收。

## 2026-11-21 实现与验证

- 一次 ASR 请求只给一种最终文本。普通对话将同一小段 PCM 实时送入原文与原生润色两条任务，避免松手后重放整条录音；这一选择有双路识别费用。语音数据只在当轮传输及有界缓冲中存在。普通输入与逐字引用的数据边界见[服务端设计](../../docs/technical/design-server.md#ward-实时转写与正式答复朗读)。
- 使用同一合成音频对照旧模型与新模型，覆盖通分提问、负三改口和中英混读。原文通路均保留改口，新模型的整理通路省略了负三试探，故保留「查看原话」；所测试的三条均识别出关键数学词或英文单词。最终双路实现从模拟松手至 WebSocket 终稿分别为 1.30、1.36、1.29 秒。三条合成样本不用于估算童声准确率或线上 P90。
- 同文 Flash/Plus 音频均已生成。用合成音频回转验证负号作用范围及分数读法，数值保真检查与人工听感分开验收。样例位于本地忽略目录 `output/ward-speech-qa/`。
- 服务端全量回归 1453 passed、4 skipped、3 subtests passed；Flutter 179 passed，analyze 通过，Android debug APK 构建成功。真实 PostgreSQL 集成回归修正了测试夹具的建库前置，使临时库包含迁移 38 的外键名称和迁移 40 的排他约束。本地业务库 duxue-test 只读核实为 20261121_40 (head)。本功能复用既有消息 JSON 字段。
- Android 模拟器使用独立临时库、真实绑定和预置正式答复验证查看整理稿和点读。物理手机锁屏，尚未完成家庭环境录音、扬声器听感及儿童样本验收。当前保留 spec 等待 Gate 2。
