# 答疑主流程由 JSON 驱动

## 验收标准与实施清单

- [x] **阶段一，固定基线。** 以真实 Ward 入口和固定模型、工具输出覆盖正常引导、上下文续问、图片缺失或歧义、澄清、发音、输入与输出安全拒绝、模型故障、审核修复和预算耗尽。对齐 WorkflowOutcome、实际展示、会话与题目事实、调用次数、重试与重复提交。以测试账号采集同环境安卓提交至首次可见反馈及完整回复的耗时，记录样本量、模型和配置版本。
- [x] **阶段二，执行声明式主图。** 在 Server 的 agent_specs/runtime.py、catalog.py、registrations.py 与 application/workflows/tutoring_workflow.py 中复用已有解释器与条件协议。拆出节点，节点产出事实或受控结果，由图选边。保留现有子图、事务与权限，基于当前发布包显式升级新图并验证旧快照；保留历史回放。入口测试只改一条合法边即可改变实际访问路径和回放；跳过输出审核、泄露裁判或错误进入写入分支的图在发布前被拒。
- [x] **阶段三，对比与灰度。** 固定快照与输入，在独立测试状态运行旧、新入口，比较归一化后的回复、调用及持久化结果；注入超时、重试、并发重放和写入失败。按新会话固定路径，验证失败时切回。安卓通过本地测试 API 验证真实交互，与同条件基线比较调用次数、失败率、首次可见反馈/完整回复 P50 和 P95。记录样本规模与波动，小样本不足以支持生产结论时明确标注。优先用测试环境验证切换，生产流量与测试数据分别记录。
- [x] **阶段四，开放受控路径调整。** 更新 Admin workflow-policy、草稿校验、发布链路与 Server 编译器，只对已迁移流程开放满足约束的拓扑变更，核对未授权节点、危险路径、无界循环、非法出口的负例。用测试环境走通一次合法改边的草稿、发布、实际运行及回滚。审阅其他域，列明哪些可以受益、哪些已有图驱动或只需原子节点。同步 agent_specs/README、领域设计和笔记。

## 验证与决策

- 每步先跑针对性服务端测试；完成后跑服务端全量、Admin 测试及构建。若变更涉及 App 或数据库，按仓库约定补对应验证。
- 建议初始性能门槛：固定依赖的同机对照中，成功路径无额外模型调用、无新增串行审核；样本充足的同环境端到端 P95 同时上升超过 10% 和 300 ms 时暂缓扩大流量。以重复测量区分模型服务波动与执行器开销。
- 用户已确认四阶段实施和自主验收。设备、测试发布、延迟与覆盖范围分别记录。

- 最终服务端 1409 项全部通过，包含真实 PostgreSQL 迁移与 Go 网关二进制集成。Admin 66 项全部通过，类型检查与生产构建通过。已只读核对业务库 duxue-test 位于 20261120_38，agent_runs.graph_version 为既有 varchar(40) 列。

- 在独立 PostgreSQL、Redis、Admin、API 和合成 Ward 上完成升级，保留共享测试环境的工作草稿与发布。Chrome 在管理台把“按任务读取近期自述”改为“直接生成”，保存后刷新回读。试图把回答节点接回写题节点时保存接口返回 422。测试发布从 R1 切到 R2，API 加载新摘要后端到端运行，再回滚 R1 并用后续请求确认 Run 使用 v1。两版并发同一指令都只有一个 Run、一条输入，另一请求 409，随后重放返回同一结果。
