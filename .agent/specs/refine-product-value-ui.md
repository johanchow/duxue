# refine-product-value-ui spec

## 做什么 / 为什么

将三个静态 UI demo 调整为更清晰地体现「孩子自主、家长支持而非监控」：Guardian 保持简洁但可快速传递信息；Ward 对学习观察充分知情并可控；复盘坚持先自评、后呈现事实。

## 验收标准

- [x] Guardian 全局仍为 3 个主导航，但在「孩子」页提供常驻、可多选孩子的「传递」入口，并支持文字、语音、截图输入；详情页保留对应任务池入口。
- [x] Guardian 的进行中状态不展示「有效学习」「专注占比」等解释性/评判性数据，仅展示计划进度与设备知情状态；行为结论仅在 Ward 自评完成后进入报告。
- [x] Ward 在学习观察中可清楚看到关联任务、已记录时长，并能暂停或结束记录；界面不展示实时专注判断。
- [x] Ward 完成计划后先完成明确的盲评问题；今日双轨反馈在提交后生成，历史成长信息始终可查看。
- [x] Ward 成长页以对照时间线和一条可选择采纳的行动建议为核心，而非只有摘要性 AI 结论。
- [x] Guardian 的今日报告在 Ward 未自评时显示等待生成；过往报告始终可看，生成后的报告以完成事实、学习节奏理解和正向沟通建议为首要信息，量化数据降为辅助证据。
- [x] 三个 mockup 的内联脚本通过静态语法与引用检查；新增控件的演示交互（切换、暂停/结束、盲评提交、今日报告生成、传递入口）已写入原型状态机，待人工浏览器验收。

## 实现计划（Gate 1：填完等人确认，不许自转）

- 影响文件：
  - `docs/mockups/guardian-home.html`：在 3 Tab 架构内增加全局「传递」入口及简洁的对象选择/内容输入 sheet；去除进行中卡片的「学习」数字，保留任务进度、设备状态与当前计划。
  - `docs/mockups/guardian-ward-detail.html`：今日页只保留计划进度与设备状态；今日报告在 Ward 自评前显示等待生成，过往报告持续可看；已生成报告按完成事实→节奏理解→沟通建议→辅助量化证据呈现。
  - `docs/mockups/ward-home.html`：增加学习观察控制 sheet（关联任务、时长、暂停/结束）；将口述总结改为可提交的盲评；今日双轨反馈在提交后生成，过往成长持续可看。
  - `.agent/notes/003-value-aligned-ui.md`：记录信息架构、观察知情权与盲评边界的设计决定及验证结果。
- 测试计划：以本地静态服务器加载三份 HTML，逐项人工验证验收标准中的状态切换与关键交互；用 `git diff --check` 检查 HTML/CSS/JS 格式错误。
