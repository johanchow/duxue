# 首次图片提问的泄露裁判边界评测

## 做什么 / 为什么

用户撤销上一轮 Companion 进度流，要求实际评测：首次上传题图、文字只有“这题怎么做”时，现有独立泄露裁判在答案边界上的误判率。用户在本轮直接指定评测目标，视为 Gate 1 授权。

## 验收标准

- [x] 撤销上一轮全部未提交的流式交互代码、测试和文档。
- [x] 构造含题图参考题面、待审核回复、预期泄露标签的诊断样本；参考题面不进入现状裁判输入。
- [x] 用生产同一 `tutoring.leak-judge` 组件、提示词和模型运行多次采样，分别报告误拦、误放、无有效裁决。
- [x] 用同一句回复在“8 厘米是已知量/待求量”两个题图下做不可区分对照，并单独评测加入题图转写后的裁判结果。
- [x] 增加无网络单测，确保现状输入不夹带题图参考题面、错误响应不算正确裁决。
- [x] 记录样本、结果、局限和后续决策；测试全绿并 review diff。

## 实现计划

1. 只撤销进度流涉及的文件，确认工作区无其他改动。
2. 在 `evals/judge_data/first_image.jsonl` 建独立诊断集；`evals/judge_boundary.py` 调生产裁判并输出 JSON 报告，不改生产行为。
3. 加无网络测试；本机运行现状组和题图摘要对照组；记录误拦/误放与样本级稳定性。
4. 更新离线评测文档与 `.agent/notes/`；跑服务端测试、`git diff --check` 并审阅变更。

## 口径

样本为合成的题图转写和拟展示回复，标签由 AI 先标为 `proposed`；不能将通过率外推为线上误判率。每个样本重复采样 3 次是稳定性观测，不等于 3 个独立题目。真实生产流程还会经过主模型与重试，本评测只隔离裁判。
