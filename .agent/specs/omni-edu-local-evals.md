# Omni-Edu 210任务与独立本地评测

## 做什么 / 为什么

按用户确认的三类能力/九科配额制作210条评测任务，存放duxue-server/evals/；本地读取用例、本地调用模型和独立评分，不读取/导入Langfuse Dataset，不依赖其Evaluator或Score。保留现有线上执行入口。用户最新请求授权本地独立路线，覆盖此前默认云端用例/评分路线。Gate 1 已由用户明确确认，本轮实施完成后等待 Gate 2 验收。

## 验收标准

- [x] evals/data/omni-edu-v1/包含210个独立任务，按主目的放teaching-correctness114（学科42/诊断72）及guidance-logic96；curriculum_grounding与通用类均为0。
- [x] 语数外各30（学科6/诊断10/引导14），其他六科各20（4/7/9）；至少105为有题面和依据支持的高考层级，尽量每科至少50%。若严格来源/内容审阅无法满足，不伪造标注、不用低学段或大学题凑数，保留缺口与证据并报告。
- [x] 保存固定上游commit、原始uid、行号/记录哈希、原文引用及许可信息；proposed标签不冒充教师confirmed。高中来源、高考真题、高考同等要求分别标记，不凭关键词/正则定学科难度。
- [x] 被测输入隔离原system与末条参考assistant；上下文/诊断中的嵌套gold只进评分侧。固定历史显式标记；合成学生错误/多轮脚本标synthetic，保持题目家族及开发/封存隔离。

- [x] python -m evals.local validate --data evals/data/omni-edu-v1 无密钥/不联网可运行；检查数量/来源/配额/图片/协议/参考隔离与家族分组。
- [x] python -m evals.local run --data evals/data/omni-edu-v1 --config-snapshot <快照> --out <目录> 可独立执行；支持dataset/subject/高考层级/case筛选、采样次数和有界并发，不调用Langfuse任何接口或自动上传。
- [x] 诊断/引导复用生产TutorTurnLoop，不放宽答案保护；完整解题使用显式evaluation-only执行目标，固定模型与解题指令身份，不能把完整解题结果当生产引导通过。

- [x] 报告记录数据/业务配置/模型/评分定义摘要、实际交付、错误与not_run，按任务/检查点分母及学科/高考子集/执行目标分报。自动评分未校准，不宣称高考准确率认证。
- [x] meaningful回归覆盖离线运行不接Langfuse、参考泄漏、非法来源/图片、完整解题与辅导边界、缺分错误、多轮真实历史、筛选与报告分母；相关测试全绿。
- [x] 文档与命令唯一说明并入docs/technical/eval-offline.md，数据目录README仅入口链接与来源；notes沉淀、git diff review。不自动运行210条付费模型评测、不上传/发布/提交。

## 实现计划（Gate 1：已确认）

1. 内容审阅与来源固定：从已下载原始快照建立逐条选样账本，按科目/三类目标挑选与改编；优先核实高中九科缺口，保留已排除理由与高考层级依据。数据放evals/data/omni-edu-v1/，不写入只读bootstrap快照。
2. 数据制作：统一采用现有dialogue-eval.v2单轮/多轮协议，必要的来源/执行目标在批次manifest中维护；原始末轮示范保留为评分参考。新增数据工具和严格validator，默认不得静默截断历史或丢图。
3. 本地入口：新增evals/local/模块（__main__/dataset/execution/report），避免导入evals.platform连接；复用现有runner/graders/semantic。入口启动前禁用OTEL/远端观测，读固定本地配置，真实模型保持网关与Admin快照约束。
4. 完整解题适配：42条使用显式独立执行目标，明确model/prompt身份和独立评分；现有生产Tutoring不修改披露权限。代码改造遵守单一事实源，优先复用组件/网关，不创建通用第二套AI平台。
5. 测试与文档：tests/unit/evals新增本地入口、数据与报告红绿回归，mock模型不走外网；全量数据静态验证及相关测试，修改文件lint/diff检查。提供单例/少量/全量命令与实际可执行的配置前提。
