# 已提交答案先反馈；裁判改为结构化事实

日期：2026-10-30。

问题证据见 [trace 排查笔记 176](176-answer-verdict-trace-review.md)。规则事实源：[已提交答案的反馈](../../docs/technical/domain-tutoring.md#已提交答案的反馈)；诊断用法见 [离线评测](../../docs/technical/eval-offline.md#64-为什么-v1-没有-llm-judge)。本次是 bugfix，无新功能计划卡点。

## 实现与取舍

- 主模型版本 `tutoring.turn@v20` / `tutoring.turn.system.v20`，共享提示词的备用组件升到 v3。已提交的计算/问答答案先独立核验、明确反馈对错；延续先前提交，不让“有没有算对”退化为反复索要过程。答对不强制追问，答错的重新计算留给孩子。没有增加语义关键词/正则或新模型调用。
- 仅重写直接生成 leaks/reason 的长规则仍不稳定：正常提示偶发误拦、给新结果被错误分类、缺题面确认偶发误放。最终文字 gate 升到 `tutoring.leak-judge@v10` / `tutoring.leak-judge.system.v9`，输出六个独立语义事实，由协议归一化稳定映射到既有原因码。语义仍由独立模型裁决，代码不读取回复文字作语义判断。
- 事实 schema 只维护在 gate JSON；协议层按该 schema 验证后映射。非法/缺字段/非布尔值返回 unknown，适配器继续转为 fail-closed。`QwenLeakJudge.leaks()` 的外部返回仍为 leaks/reason，视觉配图裁判协议不改。
- `final_answer` / `complete_solution` 的重试不再回灌含正确结果的被拒草稿。真实回放曾反复把数数序列终点照抄进“提示”，去掉答案锚点并保留对错反馈和下一步动作要求。候选在 trace 中仍完整可审计。
- 做过 qwen3.7-plus 的离线判官对照，原直接判定协议下反而误拦三次已提交的正确答案，没有采用；保留主模型与判官不同模型的既有约束。最终 gate 仍为 qwen3.8-flash。无数据库变更，应用尚未部署。
