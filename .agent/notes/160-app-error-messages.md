# App 错误提示收口（2026-10-24）

- 用户连续遇到 Guardian 登录 404、注册 400 后指出 App 失败时根本没有弹出提示。设备 `com.duxue.app.debug` 最后安装于 09:09:15，早于 09:11 的登录请求和本地路由修复；安装包仍有登录状态变化时重建路由、页面卸载后因 `mounted` 检查丢失 Snackbar 的问题。即使路由稳定，Snackbar 也会自动消失，键盘打开时不够显眼。
- 审查其他页面发现：多数错误只显示短暂 Snackbar；孩子档案、报告、分析配置和若干操作直接插入 `$error` / `$e`，把 Dio 请求地址、异常详情或服务端原文暴露给用户；绑定失败文案甚至要求查看 Flutter 终端日志。
- 先用两条界面测试复现：档案加载 503 显示技术异常；注册验证码 400 只在 Snackbar 中出现，表单内没有持续提示。两项均先红后绿。
- 新增 `core/user_error_message.dart`，按网络错误和确定的 HTTP 状态码给出稳定、可操作的通用文案。具体业务仍可在调用处加“加载报告/保存/删除”等动作；Guardian 验证码和账号不存在继续使用登录页专属文案。未识别异常用安全兜底，不展示请求 URL、响应体和异常字符串。
- 登录与注册失败改为表单内持续显示错误，错误发生时收起键盘，标记实时辅助朗读；用户修改邮箱/验证码或重新提交时清除。注册 400 的测试运行真实 `routerProvider`，覆盖路由状态变化后仍可见。其他直接显示技术异常的页面和操作均改用通用文案。语音服务端错误码映射到用户文案，避免把上游 ASR 或配置错误原文显示给用户。
- 完整 App 测试 100 项、Server 测试 634 项通过；`flutter analyze` 无问题。使用本地 `config/dart-defines.local.json` 构建 debug APK，通过 `adb install -r` 覆盖安装到已连接手机，保留应用数据；最终包的 `com.duxue.app.debug` `lastUpdateTime` 为 09:52:36。正式分发渠道仍需单独发布。
