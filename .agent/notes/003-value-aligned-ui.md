# 价值对齐 UI 原型决策

- Guardian 保持「孩子 / 决策 / 我的」三 Tab，避免把洞察与传递拆成高频导航负担；「传递」改为孩子页常驻快捷入口，可多选 Ward 并使用文字、语音或截图输入。内容先进入任务池/待确认状态，不能改写 Ward 已确认计划。
- 学习进行中只展示 Guardian 必须知情的设备状态、计划状态和任务进度；不展示实时「有效学习」或专注结论，避免产品滑向实时监督。
- Ward 必须始终知道学习观察是否开启、关联哪项任务，并能在交互端暂停或结束；实时页面不显示专注判定。
- 复盘的顺序是先让 Ward 提交自己的感受，再生成当天的双轨记录及 Guardian 报告；历史成长与历史报告始终可查看，不以“锁定”作为产品概念。客观记录使用“可能”“一起发现”等事实性、非道德化语言。
- Guardian 报告的阅读顺序固定为：完成事实 → 学习节奏理解 → 正向沟通建议 → 辅助量化记录。
- 验证：`git diff --check` 通过；三份 HTML 内联 JavaScript 经 `node --check` 通过；已检查新增控件的 ID 与事件引用。`tidy` 在本机以旧 HTML/字符集模式解析 UTF-8/HTML5，输出不适合作为该原型的有效检查结果。
