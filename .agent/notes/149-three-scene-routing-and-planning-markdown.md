# 三场景路由边界与 Planning Markdown 回复

日期：2026-10-22

- 现象：上一版意图 Prompt 把 Tutoring 限于知识提问，未明确普通探讨、闲聊属于该场景；Planning 的缺信息文案固定逐任务输出 Markdown 列表，与统一按内容排版的要求不符。
- 决策：`planning` 管理具体任务或作业的新增、修改、删除、查询与时间安排；`reflection` 总结、反思、回忆某天自己的学习或工作经历和表现；其余咨询、作业题探讨、举例和闲聊由 `tutoring` 处理。`unclear` 只用于无法理解或跨场景动作并列且主动作不明。路由仍由模型提议，不新增关键词门禁。Focus 只用于理解省略和指代。
- 回复：Planning 的模型回复以 Markdown 自然分段；确定性澄清文案以缺失字段汇总为一个 Markdown 段落，已处理操作另起段落，不强制按任务列项。App 继续使用 `ChatMarkdownBody`。
- 验证：先写三个失败测试，再修改 Prompt 与文案。新增 8 条场景边界离线样例；全量服务端测试 604 项通过，改动文件 Ruff 与 `git diff --check` 通过。仓库级 Ruff 仍有 368 条既有告警，分布在本轮未改文件。项目真实模型对原始“记录一下这些任务作业”及另外五句边界样例均返回预期意图。
