# 作业记录意图与待补创建去重

日期：2026-10-22

- 现象：带图片的“记录一下这些任务作业”被 `companion.intent` 提议为 reflection；随后 Planning 虽提取 8 个创建请求，但因缺预计时长停在 Slot；“好的，确认”又生成同样 8 个 Slot，草稿没有 Task。
- 根因：意图 Prompt 的 planning 定义仅写“安排或修改”，没有明确“记录/登记/创建任务”；路由器采纳错误提议。待补创建只按 `command_id:operation_index` 去重，跨轮同名请求被当作新操作。澄清回复把待补操作摘要和所有问题压成一句话，长清单难读。
- 修复：意图 Prompt 升级 v4，明确记录作业属于 planning、复盘只描述已完成学习，不新增关键词门禁；补入无图片及旧 tutoring 焦点的离线回归样例。确定性应用层按规范化标题复用唯一待补创建候选和 Slot，补时长则回答原 Slot；草稿只有待补候选时纯复述不增加版本，已有 Task 项时继续执行刷新。澄清回复改为 Markdown 列表，并只单独汇报已处理操作。
- 验证：红绿复现测试覆盖纯复述、复述时补时长、Markdown 列表和 Prompt 契约；服务端全量测试 603 项通过，Ruff 检查通过。联网调用项目配置的真实意图模型，文本“记录一下这些任务作业”返回 `planning`；后续线上表达仍需观察。
