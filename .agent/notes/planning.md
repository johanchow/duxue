# 计划

事实源：[domain-planning](../../docs/technical/domain-planning.md)。

## 目标

Ward 登记任务、排进当天计划并确认。同一句话可新增、修改、暂不安排或删除。时长和 07:00–22:00 只是软建议。

## 状态

- 已落地：任务池与入计划分离、澄清、引用解析、标题冲突、半开区间冲突、上海本地日、删除门禁、软建议、确认卡单按钮与历史快照、Thread 最近 8 句窗口。
- 运行时仍是一次 `plan_intake` 再确定性 `apply_operations`，不是自由选工具循环。
- 未做：已经开始执行的计划怎么改；一个任务拆成多段时间。

## 决策

- 有标题和预计时长立刻入池，不经确认。排进当天计划才要开始时间。确认后只有时间完整且无冲突的项写入正式日程。
- 模型不生成任务 ID、不判定无冲突、不确认正式计划。
- 引用顺序：结构化 ID、澄清槽、界面焦点、规范化名称精确匹配。无受权候选就拒绝，不签发空选择槽。对上已有任务就拒绝同名新建，除非 Ward 明确「仍然新增」。
- `plan_date` 固定 `Asia/Shanghai`，时间戳存 UTC。版本冲突回 409，不包成 200。
- 保存草稿和等待确认拆开。确认恢复只读已审阅草稿。还有未完成澄清就不能确认。「这次不安排」是跳过，不是字段已填。
- 带开始时间或相对顺序的新增，校验失败或还在等时间澄清时不能留下新任务。
- 删除、从草稿拿掉、暂不安排是三件事。已入正式计划的删除只写修订草稿，确认时同事务删除。
- 软建议不写入草稿。采纳绑定交互、草稿、版本和建议指纹。规则见 domain-planning「时长与计划时间的软建议」。
- 场景由模型提议。计划管具体任务的增删改查和时间。听不懂或两个场景并列才是 `unclear`。

## 注意

- 计划提示词是 f-string，示例 JSON 花括号写成 `{{` `}}`。
- DashScope HTTP 客户端必须 `trust_env=False`，失效代理会让整理一直不可用。
- 确认关掉 Run，下一句是新 Run。指代读同一 Thread 最近 8 句、合计 2400 字、不含本轮。
- `operations` 为空时不能说已记入任务池。有标题无时长只追问、不入库。
- 首页缺开始时间会用 19:00 推算、缺时长显示「约 30 分钟」，只是展示，不能写回，服务端也不默认 30 分钟。
- Dart 解析带 `+08:00` 的时间可能变成 UTC，展示前转上海固定偏移。
- 过了本地日的 `scheduled` 必须回任务池，否则再安排到今天会找不到可改任务。旧那天的日程保留。
- 同一开始时间写到多个任务上要清空并澄清。前一项结束等于后一项开始不算重叠。
- 接口字段仍叫 `assignment_id`，领域身份是 `task_id`。
- 左滑删除不能删已排期、有学习记录或 `source=guardian` 的任务。已有学习记录返回 409。
- 拒绝日志只记稳定错误码和值的形态，不记原话和标题。
