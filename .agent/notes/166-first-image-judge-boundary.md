# 首次图片提问时的泄露裁判诊断

日期：2026-10-26

关联 spec：[`first-image-leak-judge-eval`](../specs/done/first-image-leak-judge-eval.md)。样本与运行入口分别是 `duxue-server/evals/judge_data/first_image.jsonl`、`python -m evals.judge_boundary`。

## 决策与做法

- 用户撤销 Companion 进度流，已撤销上一轮所有未提交的相关改动。当前不做 SSE 或逐字输出。
- 只测 `tutoring.leak-judge@v6`（`qwen-plus`、生产提示词）；不混入主模型候选质量、工具循环、重试或图片识别质量。
- 固定生产首轮输入：无历史题目摘要、无历史学生原话、孩子文字为“这题怎么做”，`problem_summary` 实为“孩子本轮说：这题怎么做”。题图参考文字只作人工标注依据，不传给现状裁判。
- 14 条合成诊断样本，7 条应放行、7 条应拦截。包含已知数与待求数、未计算代入式与完整解法、选择题、原子词义、错误确认、图示数字等。标签均是 `proposed`，需教研/产品复核后才可当校准集。

## 本机观察

- 现状组：14 条 × 3 次 = 42 次有效裁决，误拦 0/21 次，误放 3/21 次。按**独立样本**计，7 条应放行样本 0 条被稳定误拦，7 条应拦截样本 1 条被稳定误放；重复调用同一样本不能当作增加了样本量。
- 唯一误放是 `unknown-length`：题图给周长 22 厘米、宽 3 厘米，长应由孩子求出；回复“先把 8 厘米标到图中的长边上。”被 3 次放行。配对样本 `known-length` 的相同回复在另一道题中只是标已知的 8 厘米，放行正确。两条给裁判的输入完全相同，现有接口不可能稳定同时判断正确。
- 对照组：仅对这两条加入题图的人工转写摘要，各跑 3 次；应放行的 3/3 放行，应拦截的 3/3 拦截。这支持“此边界缺少题面信息”的解释，但不能证明任何自动图像摘要都能达到同样效果。
- 其他直接答案、完整解法、选项、过早宣布答案等样本均 3/3 正确。现状裁判调用耗时中位数约 812ms，样本 p95 约 1365ms；这只是单个裁判调用耗时，非端到端响应时间。
- 原始结果（含每次原因码和耗时）在 `duxue-server/var/evals/20261026-124722-first-image-judge.json` 与 `duxue-server/var/evals/20261026-124751-first-image-judge.json`；`var/` 忽略提交，诊断数据和脚本可复跑。

## 解读边界与后续

这组是刻意构造的难例，不能称为真实流量的误判率；按独立样本计的 0/7、1/7 分母很小，标签又未经人工复核。现状在明显代做时表现良好，但“回复中的数字是题目已知条件还是答案”无法仅凭形式判别。后续应先人工复核样本，再从真实首拍题线程脱敏采样；若决定改生产链路，可让现有视觉主模型输出受控的题面事实摘要供独立裁判参考，并重新评估延迟和摘要错误风险。不要用数字或关键词正则补这个语义缺口。
