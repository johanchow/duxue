# 学习执行

事实源：[domain-study](../../docs/technical/domain-study.md)。

## 目标

Study 拥有学习会话、计时和到点开始邀请。任务是否入池、入日程、完成由 Planning 记。进行中和暂停由 StudySession 记。到点未开始时邀请开始，不自动开课。

## 状态

- 已落地：任务四态、会话开始/暂停/继续/完成、跨天放弃遗留会话、首页任务卡、StartCue 卡片。
- 读取邀请时同步打开卡片。没有现场就用 `no_observation` 和兜底句，不调视觉模型和文案模型。
- 未做：到点前的观察租约和真实场景分类。`away` 只有服务传入该标签时才不展示。

## 决策

- Task 只有 `pool` / `scheduled` / `completed` / `cancelled`。`completed` 只由 Planning 消费 `StudySessionCompleted.v1` 写入。开始学习不改任务安排状态。
- 本地日过后，未完成的 `scheduled` 回到当天任务池，同时把往日未结束的 `active` / `paused` 标为 `abandoned`（`day_rollover`）并解开任务绑定，任务池才可以左滑删除。
- 新开的、不带学习会话的答疑不继承旧线程里未结束的题目。
- StartCue 属于 Study。前一项还在进行也会打开，按钮改为继续或切换。不自动开始、不改期、不通知家长、不写学习事实。卡片 `kind` 为 `start_cue`，登记在 Companion。Planning 只提供 `start_at`。
- 首页在本地时钟的整 5 分钟以及回到前台时刷新邀请。开始提醒只排 `scheduled` 任务。当天已有自评则不排今日总结提醒。
- 无任务答疑可以不绑定任务。已有任务会话进行中或暂停时，问别的只简短回答并提醒回任务，不结束原会话。学习会话结束后答疑不自动关闭，只是不再追加新轮次。
- 暂停和继续先改本地卡片再请求服务器。暂停状态可以直接标记完成。

## 注意

- 本地通知用系统闹钟：当天从没打开 App 排不出去；Android 非精确；别的设备改了状态而本机没再同步时，已排通知仍可能响。
- 未排期任务左滑走删除接口；已有学习记录返回 409。
